## 4. 首启改造:✅ 五条全部做完并实机验收(2026-08-03)

五条都落地了,验收逐条通过,记录+三张实拍在 `docs/DESIGN_FIRST_RUN.md` §7。
落地方式里有三处后来人会关心的判断:

1. **「这是首启」怎么判**:用「**这次启动建了库**」——只有建库的那个进程拿得到刚播下的
   教程脉络 id(`getFirstRunThreadId()`)。**不新增任何持久状态**,教程被删掉就自动回落到
   捕捉目标。实测第二次启动确实回到 Unsorted。
2. **一次性收口的一次性状态**:`settings.json` 的 `firstCaptureHintPending`,
   **由建库那次启动点亮、首次捕捉花掉**。存量库从来没有这个键 → 判据天然是
   「首次捕捉且没见过」,Ocean 自己的库不会突然看到这句话。**没进数据库、没进种子。**
   一次性行为有两条 vitest 兜着(`src/stores/captureStore.test.ts`)。
3. **教程种子里那句「首次使用会请求权限」顺手改了** —— 拍板点 3 之后它不再成立,
   而拍板点 1 恰好把新用户送到它面前。现在写的是「点顶部横幅的『打开捕捉』」。

⚠️ **验收中测出来的新事实**:**注册全局捕捉快捷键会当场弹「输入监听」授权框**
(不是我们的启动代码)。默认 `captureShortcut` 是 null,所以新装用户碰不到;
但**用户在设置里录一个捕捉快捷键就会撞上**,文案里没有一处说过这件事。详见设计稿 §7.1。

💡 仍然没做的:**教程种子里的 MCP 说明还停在「一键接入 Claude Desktop / Cursor」,
实际支持六个**。Ocean 说这句「预留到以后和其他教程修订一起做」,本窗尊重这条,只改了
上面第 3 点那句(因为它被拍板点 3 直接改成了假话),没顺手扩到 MCP 这句。
