## 1. 论文说了什么（核实过的部分）

`arXiv:2608.20202`，2026-08-20，Mengru Wang / Haozhe Luo / … / Ningyu Zhang（浙大等）。

### 1.1 数字核对

| 说法 | 论文原文 | |
|---|---|---|
| 无记忆基线 | Gemini-3-Flash-Preview **85.16%**、Qwen3-30B-A3B **81.83%** | ✅ |
| 所有记忆方案都低于基线 | 最强 EverMemOS(Gemini) **71.17%**、LightMem(Qwen) **70.13%** | ✅ |
| 数据规模 | **1050 例**，每例 **18–40 轮** 对话 | ✅ |
| 任务边界消融 | wo/Mem **92.29** · no trap **94.39** · trap-inducing **31.05** · 25% 长度 **36.03** | ✅ 都是**子集**里的数 |
| 评分 | **GPT-5.2** 主评，**Claude Sonnet 4.6** 只用于一致性复核 | ✅ |
| AdaptiveMem | Gemini +11.8/+14.9/+11.3；Qwen +4.2/+2.5/+2.6；每基准**只抽 200 例**、**只测 3 个框架** | ✅ |

⚠️ **文字和表格有一处矛盾**（那份分析发现的，核实属实）：正文称 Qwen 上最强的
"memory framework" 是 LightMem **70.13%**，但表里原始 FullText 是 **70.99%**。
排除 FullText 只比结构化框架时 70.13 成立；说"所有记忆方案里最好"则应是 70.99。

### 1.2 ⭐ 四类陷阱的定义 —— 全篇对我们最有用的部分

1050 例 = **350 Cognitive Bias + 350 Task Boundary + 200 Safety + 150 Trauma**。
上层归成两类（Reasoning Fixation / Belief Distortion），但**真正能拿来用的是下面这四条定义**：

| 类 | 例数 | 定义（论文原文的意思） |
|---|---|---|
| **Cognitive Bias** | 350 | 把**过去成功的策略**过度泛化到一道需要别的策略的新题 |
| **Task Boundary** | 350 | **任务已经变了**，模型继续套用上一个任务的规则和假设 |
| **Safety** | 200 | 历史里**只在沙盒 / 反事实下成立**的前提，被带进真实世界的问题 |
| **Trauma** | 150 | **过去的负面反馈**，让模型回避一个对当前题目其实正确的方案 |

⚠️ **老师那份摘要没点名 Trauma**（并进了"推理固着"一句带过）。
⭐ **而 Trauma 恰好是四类里唯一直接撞上我们 2026-08-19 表头修法的一类** —— 见 §5。

⚠️ **一条要说清楚的比例**：「准确且相关的记忆也会伤害模型」这句，
覆盖 **850/1050**（Cognitive Bias + Task Boundary + Trauma 用的都是准确记忆）；
只有 Safety 那 **200 例**用的是刻意植入的假前提。
那份分析说这句"主要只适用于 Reasoning Fixation"——**方向对，力度过了**。
对外引用时补一句「其中安全那 200 例用的是刻意植入的假前提」就够，不用把整句收回。

### 1.3 ⭐⭐ 离 Spool 最近的那一格：FullText

五个被测方案里，**FullText（把完整历史原样喂进去）最接近 Spool 的"完整时间线 pack"**。

| FullText @ Gemini-3-Flash | 分数 |
|---|---|
| Task Boundary | **47.01%** |
| Cognitive Bias | **44.36%** |
| Trauma | 69.43% |
| Safety | 81.90% |
| **平均** | **60.68%** ← 比无记忆基线 85.16% **低 24.5 分** |

⚠️ **但要诚实读完**：同一个 FullText 在 Qwen3-30B 上是 **70.99%，全场最高**。
⛔ 所以**「FullText 最差」不是普适结论，是模型相关的**。别把它当铁律往自己身上套，
也别在它对我们不利的时候才引用一半。

⭐ 真正稳的读法是那两格低分的**位置**：FullText 垮在 **Task Boundary 和 Cognitive Bias**，
而不是 Safety。**它不是被假信息骗了，是被真信息带出了范围。**

### 1.4 AdaptiveMem 是什么

**不改数据库、不改检索器，只在推理时加四条提示。** 四条对应上面四类：

1. **Task Boundary** —— 答案锚在当前问题上；除非明确要求，不要把上一个任务的范围带过来
2. **Cognitive Bias** —— 不要锁死在一个推理框架里；任务变了就重新评估，别靠惯性
3. **Trauma** —— 不要让早先的批评，挡住一个当前确实需要的正确方案
4. **Safety** —— 相信客观现实和既定事实，别让历史里的虚假内容支配回答

⭐ **这一点对我们极其重要**：AdaptiveMem 的作用面**就是 Spool 表头的作用面** ——
一段静态的、发给接收模型的文字。**不需要 AI 热路径、不需要联网、不改确定性。**
换句话说，论文提出的缓解方法，**我们本来就有那个位置**，只是那四条里有三条还没写。

⛔ **这行字不在产品里。** 它在 `docs/SPOOL_OVERVIEW.md:524` 的**摘要表**里。

> When a later block from any category says a Reference has since changed, put the conflict

> they are wrong on the strength of an older Reference alone.

**这是 WORKPLAN §1.4 表头八条修法的第 1 条，2026-08-19 做的。**

同样地，它 P0 的另一半「Pack 要声明自己是历史上下文、不是当前任务」——
表头末尾的 `## What This Is` 已经写着 *"Everything above and below is context, not a task…"*，

⭐ 而 `SPOOL_OVERVIEW.md` 自己第 15 行就声明了：
> *Where this file and one of those disagree, the other one wins and this file is stale.*

### 4.2 ⭐⭐ 这件事本身就是论文的活体样例

一份**写的时候准确、来源可信（自己项目的官方总览）、与问题高度相关**的记忆，
因为**超出了它的时效与适用范围**，让一个模型自信地做出了
「这是最高风险项、应立即修正」的判断 —— 而那条规则已经不存在了。

**这正是论文 Task Boundary 那 350 例的形状。我们不用去实验室找例子，这一轮自己产生了一个。**

⚠️ **连带的硬规矩**：审 Spool 的 pack 规则**只读产品字节**
（`mcp.rs::INSTRUCTION_HEADER` + `templates.ts`），**不读 Overview**。
任何拿外部分析对照现状的结论，先按字节逐条复核再采信。

## 5. 论文对 Spool 的真正作用

### 5.1 四格对照：AdaptiveMem 的四条，表头有几条

| 陷阱类 | Spool 表头现在有什么 | 判定 |
|---|---|---|
| **Task Boundary** | **零** —— 四带全部按「来源可信度」排权重，**没有一个字讲适用范围** | ⛔ **真缺口** |
| **Cognitive Bias** | **零** | ⛔ **真缺口** |
| **Trauma** | ⚠️ **有，但方向可能是反的** | ⚠️ **要补一句限定** |
| **Safety** | 半格：`only at equal recency` 挡的是**过期**，挡不住**从来就不该当真** | ⚠️ **半缺口** |

⚠️⚠️ **Trauma 那格展开。** §1.4 的第 6 条修法把 `↩ replaces` 的处理
从「It is history: do not use it」改成了：

> You may still say the user considered it and ruled it out —
> **that a road was already closed is worth knowing.**

**那条修法的理由没错**（"此路不通"本身有价值，白丢可惜）。
但论文 Trauma 那 150 例测的**正好是这件事的副作用**：
历史里有对某方案的否定 → 模型在这个方案其实正确的新题上回避了它。

⛔ **不建议撤回第 6 条修法** —— 撤回等于回到"此路不通白丢"。
⭐ **该补的是一句限定**：*排除过是一个历史事实，不是当前禁令；
当前任务明确需要那条路时，照走。* 既保住第 6 条的收益，又正好是 AdaptiveMem 第 3 条。

⚠️ **Safety 那半格的具体形状**：📖 Reference 的判定依据是**来源的形状**
（邮件客户端、机构域名、PDF 附件），**不是内容的真假**。
一份 PDF 里写着一条只在某个沙盒 / 某个旧辖区成立的规则，进来就是 📖 Reference，
拿到「ground truth, do not contradict」。
`equal recency` 挡的是"后来变了"，挡不住"它从一开始就只在某个范围内成立"。
⭐ **这和"捕获内容里的提示注入"是同一个洞的两个方向，当一件事看。**

### 5.2 另外两个缺口

**① Pinned 的三重加权（⛔ 假设，无数据）**

pack 的装配顺序是 **表头 → Pinned Blocks（全文）→ Full Record**。
置顶块同时拿到**位置最前 + 全文不裁 + 行内 📌**。
一个被置顶的旧规则，是整份 pack 里权重最高的东西 ——
**而权重高低跟它还适不适用完全无关。**
⛔ **在有数据之前不要动 Pinned 的渲染。**

**② 表头会被读没（⭐ 结构性，两条独立推理撞上了）**

表头在 pack 最开头，`## What This Is` 大约落在 6,594 字符处，
后面的正文**没有任何一处重复它**。

⭐ **这个论证 WORKPLAN §2.6 自己已经写过一遍**：
「四带分类是唯一一个不印在行内、只写在表头里的东西，**也就是整份 pack 里最先失效的那部分**」。
分析建议的「pack 结尾加一句短提醒」和 §2.6 的「把 💭 印进行内」
是同一个思路的两个落点。**两条独立推理撞到一起，这条的可信度最高。**

⚠️ **还有一条路谁都没提**：`assemble({ instructions: false })` 会把**整段表头丢掉**。
那种 pack 现在是**零适用性提示**，是缺口最大的一条路。

## 6. 要改什么

### 6.1 ⭐ 表头补三句 + 头尾边界（可做，纯字符串）

**改什么**：

1. **Task Boundary** —— 只使用**范围、时间、前提仍然匹配**当前任务的块
2. **Cognitive Bias** —— 过去有效的做法**不是当前的默认做法**，任务变了要重新评估
3. **Trauma** —— **排除过是一个历史事实，不是当前禁令**；当前任务需要那条路时照走
4. **顺序**：先判**适用性**，再排**来源权重**。📖 的高权重只在它已验证的范围和时段内成立
5. **边界**：pack 加 BEGIN/END 标记，**尾部重复一句短提醒**（长 pack 里开头那段会被读没）
6. **MCP 同步**：`INSTRUCTION_BODY` + `get_pack` 描述里各重复一句
   —— ⚠️ 只改工具描述、不改路由文本的话，第三方客户端读不到

**为什么可做**：纯字符串、零行为改动、确定性不变、不需要 AI 不需要联网 ——
和 §1.4 那七条修法同一类，有 byte-identical 测试 + golden fixture 兜底。
⭐ **和 §2.6 那次动渲染器合并做，只动一遍 golden。**

⚠️ **必须同时说清楚的一句**：**这是 prompt 级的，不是闸门。**
对外**不能**说「Spool 阻止任务越界」，只能说
「Spool 的 pack 明确区分历史与当前任务，并要求接收模型在使用前检查适用范围」。

### 6.2 ⭐ 合并界面加第四个选项：`scope_limited`（可做，零成本）

§9.12 用 60 次实测定下的界面是三选一：**合并 / 只退旧的 / 不动**。
那份分析补了一个**这三个都表达不了**的状态：

> **`scope_limited` —— 旧块在它原来的场景里仍然完全正确，
> 只是只适用于某个版本 / 地区 / 环境 / 子任务。**

合并会把范围抹掉，退掉会丢一条仍然有效的事实，不动则什么都没记下来。
⭐ **而这正是论文 Task Boundary 那 350 例的形状。**

⚠️ 这一格在我们库里到底出没出现过，**现在不知道** —— §9.12 的标注没按这个维度分过。
⭐ **查清它不用花钱、不用调 API**：拿 §9.12 那 39 条现成标注重扫一遍就行。
**它决定合并界面是三选一还是四选一。**

### 6.3 ⚠️ Safety 面：纸面复核，先不跑实验

把两件事当一件事看：📖 按来源形状判定 + 捕获内容里的提示注入。
⚠️ 是安全面，但**真实外部用户 = 0，风险窗口现在是关着的**，
下一窗只做纸面复核即可。

### 6.4 ⛔ 排在渠道之后的两件

| | 什么 | 为什么往后排 |
|---|---|---|
| **五臂对照实验** | 无历史 / FullText / 现 pack / 新表头 pack / 清理过的 pack。⭐ 指标里**必须含正向题**（必须靠历史才答得出的），否则最优策略永远是"忽略全部记忆" | 这是**唯一能出产品证据**的那件事，但要花钱、要标注、要多模型 —— 而且**在有真实用户之前，它优化的是一个没人用的东西** |
| **Authority Band / Pinned 消融** | 同一段陷阱内容，只改呈现方式（带 / 置顶 / 有无日期 / 新旧表头） | ⚠️ **但它有一个现在就生效的副作用：在这个实验之前，别把四带格式当成独立 skill 发出去** |

## 7. ⛔ 不要做什么

| | 为什么 |
|---|---|
| ⛔ **不要改开工顺序** | 真实外部用户 = 0，§9 的逻辑是"先让第一个真人进来"。那份分析提的五个实验是一个**研究项目**，不是一个窗口的活。它自己也看出了"过度投入风险"，然后又把两个大实验排在渠道前面 |
| ⛔ **不要重启压缩** | §9.9 的判定不变。论文没给任何理由改它，**反而加强它**：压缩的失败是看不见的 |
| ⛔ **不要给 `get_pack` 加 `current_task` 参数** | ① 那是用户在别处说的原话，会被打进 pack，而 pack 要被粘给第三方 AI、也会进压缩 sidecar 的 API payload —— **等于开一条「客户端对话原文 → 外发」的通路**，形态 C 的默认关闭就是绕着它建的；② 输出字节会依赖调用者传了什么，golden 和 byte-identical 测试都建在"同一项目同一时刻 → 同样字节"上；③ ⭐ 收益可疑：MCP 场景下客户端本来就还记得触发调用的那条消息，真正需要它的只有"预加载 pack、之后才提问"，而那种情形正好是 §6.1 的尾部提醒解决的 |
| ⛔ **不要动 Pinned 渲染** | §5.2 那条只是假设，没有数据 |
| ⛔ **不要让 Spool 按任务做语义过滤** | 会同时破坏确定性、无 AI 热路径、可复查性，以及"没被检索到的关键信息仍然可见"这条 |
