## 1. Ocean 的原话(2026-08-15)

原始三条(backlog §1.4):

1. **弹窗可以直接打字**,不用每次先点一下;

## 2. 取证 —— 直达打字为什么时灵时不灵

### 2.1 这不是「文案超前」,是一处真的断了

官网 `01 · SAVE` 现在写着 "The confirmation appears with the cursor already in a note box"
(中文版同义)。backlog §3.1 第 4 件要求先定性。**定性结果:产品确实实现了这件事,
但有一条路走不通。**

### 2.2 断的是哪条路:**在 Spool 自己窗口里捕捉**

判断条件在 `src-tauri/src/capture.rs` 的 `ax_source_app_pid()`:

```rust
if pid == std::process::id() as i32 || Some(pid) == crate::overlay::helper_pid() {
    None            // ← 返回 None 就等于「不抢焦点」
```

返回 `None` → `ACTIVATE_ON_SHOWN = false` → `on_overlay_shown()` 直接 return →
浮窗那个进程**永远不会变成活跃应用**。

而 macOS **只把键盘发给活跃应用**。于是:批注框拿到了 DOM 焦点(`CaptureOverlay.tsx`
的 `annotationRef.current.focus()` 是执行了的),**但键盘还在主窗**。
用户打的字进主窗,必须先点一下浮窗。

### 2.3 根因:一个前提在 2026-08-01 中午失效了,判断条件没跟着改

| 时间 | 提交 | 发生了什么 |
|---|---|---|
| 02:01 | `a3cfba2` | 走辅助功能抢焦点。⭐ **当时浮窗是主进程的一个窗口** |
| 12:20 | `74b87f1` | 浮窗搬进独立进程 `spool --overlay` |

`a3cfba2` 那一版的条件只有一句 `if pid == std::process::id()`,而且当时**是对的** ——
浮窗和主窗同属一个进程,主进程活跃 = 浮窗能收到键盘。

`74b87f1` 搬进程时,条件补上了 `|| Some(pid) == helper_pid()` 这一半(防止连续捕捉时把
焦点「还」给浮窗自己),**但 `pid == std::process::id()` 那一半原样留着**,连带留着的还有
它的依据 —— 那句注释今天还在文件里:

> `Spool is already the active app (Ocean's 2026-08-01 test: that case already works untouched)`

⚠️ **那次实测是当天上午做的,在搬进程之前。** 搬完之后「主进程活跃」不再蕴含
「浮窗进程能收到键盘」,因为**激活是按进程算的** —— 这正是当初把浮窗搬出去的理由本身。

### 2.4 权限不是原因

系统 TCC 实测(2026-08-15):`kTCCServiceAccessibility | com.oceanjin.spool | 2`,
`kTCCServiceListenEvent | com.oceanjin.spool | 2` —— **两个都已授权。**
所以 Ocean 遇到的「要点一下」不能用「没给权限」解释。

### 2.5 ⚠️ 但权限确实是另一半原因 —— 而且对外文案少说了

没有辅助功能授权时,`ax_source_app_pid()` 第一行就 `return None`,**从任何 app 捕捉都不会
抢前台**。代码自己的日志把这件事说得很直白:

```
[capture] AXFrontmost refused — note box needs a click to type into
```

**而下面三处对外文案都只说了辅助功能的一个用途(删掉第二次 ⌥),没说它还管直达打字:**

| 位置 | 现在怎么说的 |
|---|---|
| `site/index.html` `perm-p1` / `perm-p3`(中文版同步) | 「Accessibility 是可选的:捕捉之后它删掉第二次按键」 |
| `README.md:108` | 同上 |
| `docs/PRIVACY.md:44` | 同上 |

用户拒了辅助功能,**还会额外丢掉直达打字**,三处都没写。这条要一起补(§6)。

## 3. 三条各自要改什么

### 3.1 第 1 条:一律抢占

**改动面只有一处**:`ax_source_app_pid()` 去掉 `pid == std::process::id()` 这一支,
保留 `helper_pid()` 那一支。

```rust
// 保留:连续捕捉时浮窗自己在前台,"还"焦点给它会把用户困在浮窗里
if Some(pid) == crate::overlay::helper_pid() { None } else { Some(pid) }
```

**为什么不碰铁律**:被激活的是 **helper 进程**,不是主进程。主窗不会因此跳到最前面 ——
把浮窗搬进独立进程,本来就是为了让这两件事可以分开。
关闭时 `RESTORE_FOCUS_PID` 会拿着主进程的 pid 把焦点还回去,用户回到他原来待的地方。

⚠️ **这一支删掉之后,注释里那句 2026-08-01 的依据必须一起删。** 它是这个 bug 的来源,
留着下一个人会照它再加回去。

### 3.2 第 2 条:作废(见 §1.1)

不实现。

### 3.3 第 3 条:提示 ⌘Z —— ⚠️ 这条有个真冲突,不是加句文案

批注框现在的 placeholder 是 `留一句想法…（Enter 保存，Esc 跳过）`
(`src/overlay/CaptureOverlay.tsx`)。第 3 条是想让它也提一句 ⌘Z。

**但 ⌘Z 在浮窗弹着的时候是「全局快捷键」,不是文本框的撤销。**
`register_undo_shortcut()` 在浮窗显示期间抢注 ⌘Z(抢不到就退回 ⌥Z),它撤销的是
**整条捕捉**;`CaptureOverlay.tsx` 的 `onKeyDown` 只处理 Enter 和 Esc,**没有拦 ⌘Z**。

⚠️⚠️ **第 1 条做成之后,这个冲突才第一次真正暴露出来。**
以前键盘根本不在浮窗上,用户不会在批注框里按 ⌘Z;第 1 条一通,用户就会边打字边按 ⌘Z ——
**他想撤掉刚打错的两个字,实际撤掉的是整条捕捉。**

而第 3 条要做的事,正是**把这个 ⌘Z 明明白白写给用户看**。所以两条必须一起定,
不能只加文案。三条路在 §5 问题 ② 里。

## 4. ✅ 那条对不上的观察 —— 查清了,Ocean 是对的,而且不止一个毛病

Ocean 说「**目前只有 word 的情况是会抢占的**」。
写这一稿时我判断「按代码,从任何非 Spool 的 app 捕捉都应该抢到」,**判断错了。**
装机埋日志之后,他的观察逐字属实。

**真因:`ax_focused_app_pid()` 问的 `AXFocusedApplication` 有大片盲区。**
2026-08-15 实测日志(两个授权都在,`ax_granted=true`):

| 捕捉时前台是 | `AXFocusedApplication` 答 | 后果 |
|---|---|---|
| Word | `Some(pid)` ✓ | 正常 |
| **浏览器** | **`None`** | `source_pid=None` → 不抢焦点 |
| Spool 主窗 | `Some(68693)` ✓ | 正常(§3.1 修好之后) |
| **浮窗自己**(抢完之后回查) | **`None`** | —— 连自家 Accessory 进程都报不出来 |

⭐ **一个 `None` 同时造成两个症状**,这就是为什么「打字不进批注框」和「撤销是老模式」
总是一起出现:`source_pid=None` 既跳过激活,又让全局 ⌘Z 被注册(§3.3 的分流条件)。

⚠️ **教训,值得记住**:`None` 和「没事可做」在类型上是同一个值。
**一个会静默退化成 no-op 的查询,出错时看起来就像它答对了。**

## 5. 要 Ocean 拍板的三个问题

### ① 主窗在前台时,浮窗抢焦点会把主窗一起抬起来吗?

**不会**,理由见 §3.1。但这条值得他知道:抢的是 helper 进程,主窗留在原处;
浮窗关掉之后焦点回到主窗。**如果他觉得「在 Spool 里捕捉时浮窗跳出来抢键盘」本身很吵,
那第 1 条就该只对「从别的 app 捕捉」生效** —— 这是另一个选择,不是 bug。

### ② ⌘Z 在批注框里,应该撤什么?(§3.3)

| 路 | 做法 | 代价 |
|---|---|---|
| **甲** | 批注框有焦点时,⌘Z 让给文本框(撤打字);撤销整条捕捉改用别的键 | 要另找一个键,而且用户已经习惯了 ⌘Z 撤捕捉 |
| **乙** | ⌘Z 始终撤整条捕捉;placeholder 就照实写「⌘Z 撤销这次捕捉」 | 打错字没法撤,但**语义唯一,不会误伤** |
| **丙** | 框里有字 → ⌘Z 撤打字;框是空的 → ⌘Z 撤捕捉 | 最贴直觉,但**同一个键两种意思**,和当初砍掉长按 ⌥ 的理由是同一类结构性歧义 |

⚠️ **丙看着最聪明,但它就是「单击/双击/长按挤在同一个键上」那个老毛病的翻版**
(见 `capture-note-first` 里收集面板被整体删除的根因)。**建议乙。**

### ③ 提示语放哪、写多长?

placeholder 现在已经有两条(Enter / Esc),再塞 ⌘Z 会变成三条,在 340px 宽的浮窗里挤。
要么换一行更短的写法,要么把 ⌘Z 提示只在**真按过一次**之后才显示。要他挑。

## 7. 给 Ocean 的三步实测(§4 用)

每一步都是:复制一段字 → 双击 ⌥ → **不要点任何地方**,直接打两个字 → 看字进哪儿。

1. **在 Word 里**:打开一个文档,点进正文,复制一段字,双击 ⌥,直接打字。
2. **在浏览器里**:打开一个网页,选中一段字复制,双击 ⌥,直接打字。
3. **在 Spool 自己窗口里**:随便打开一个项目,复制一段字,双击 ⌥,直接打字。

每一步记一下:**字进了批注框,还是进了原来那个 app。**

(按 §2 的预测:1 和 2 应该进批注框,3 会进 Spool 主窗。如果 2 也进了原 app,
就是 §4 说的第二个毛病。)

### 9.2 改了哪些

⚠️ **一共修了三个独立的缺陷,不是一个。** 前两个是这一稿最初只看到的,
第三个是装机之后靠日志才挖出来的(§4),而它才是浏览器那条路的真凶。

**Rust**

1. **过期的例外**(§2.3)—— `ax_source_app_pid()` 删掉 `pid == std::process::id()` 那一支,
   连同它那句 2026-08-01 的过期依据。原地留了一段**别再加回来**的注释。
   → 修好「在 Spool 自己窗口里捕捉」。
2. **⌘Z 的分流**(§3.3)—— `show_capture_overlay()` 的全局抢注改成有条件;
   `on_overlay_shown()` 改签名收 `AppHandle`,`AXFrontmost` 被拒时补注册;
   `overlay.rs` 的 `"shown"` 那一路把 `app` 传进去。
3. ⭐ **`AXFocusedApplication` 的盲区**(§4)—— 新增 `frontmost_window_owner_pid()`:
   问**窗口服务器**(`CGWindowList` 的 `kCGWindowListOptionOnScreenOnly`,取最前面
   `kCGWindowLayer == 0` 的那个窗口的 `kCGWindowOwnerPID`)。
   `ax_source_app_pid()` 改成 `ax_focused_app_pid().or_else(frontmost_window_owner_pid)`。
   → 修好**浏览器**那条路(也就是最常见的那条)。
   ⚠️ **兜底而不是替换**:AX 答得出时它更精确(答的是「键盘真正要去哪」);
   窗口服务器答的问题略粗,但它**永远答得出**,而且不需要额外授权
   (owner pid 和 layer 不是屏幕录制管的那些内容)。`core-graphics` 本来就是依赖。

⚠️ **顺手修掉一个本稿自己引入的竞态**:第 2 条最初判断「要不要注册全局 ⌘Z」时
**重新读了 `ACTIVATE_ON_SHOWN` 这个原子量**,而 helper 回的 `"shown"` 是在 stdout 读取线程上
处理的 —— `on_overlay_shown` 可能已经把它 swap 回 false,于是**恰好在刚拿到焦点的那几次捕捉上
把全局 ⌘Z 又装了回去**。改成局部变量,不再有时序依赖。

⭐ **两条路是自洽的,不是两套逻辑**:浮窗拿到前台 → 键盘到得了 webview → 由浮窗自己判断丙的两半;
浮窗拿不到前台 → 用户打不了字 → 框必空 → 全局 ⌘Z 撤捕捉。**丙的两半各自只有一个实现。**

**前端**

- `CaptureOverlay.tsx` textarea `onKeyDown` —— 加 ⌘Z 分支:
  `e.currentTarget.value` 非空就 `return`(交给文本框原生撤销),空就 `preventDefault` + 撤捕捉。
  ⇧⌘Z 是重做,排除在外。
- 脚注 ↩ 按钮 tooltip:`撤销刚才的捕捉` → `撤销刚才的捕捉 · ⌘Z`(字典同步)。

**对外文案(§6,实际是五处不是三处 —— 隐私页中英各有一份表也在说同一件事)**

`site/index.html` `perm-p1`/`perm-p3`、`site/privacy.html` 权限表、
`scripts/site-zh-strings.mjs`、`scripts/site-zh-privacy.html`、`README.md`、`docs/PRIVACY.md`。
中文页由生成器重跑,没有手改 `site/zh/*.html`。
