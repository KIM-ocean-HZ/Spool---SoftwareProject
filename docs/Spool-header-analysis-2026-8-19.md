这份 header 我现在就在读，所以先说一件事：**我确实在按它执行**——`#12` 这种编号我会照着用，`⚠️ ... see #N` 我会真的跳过去读，`ai note:` 我不会当成你的判断。注解层做得比我见过的绝大多数上下文格式都好。

问题不在四带的定义，在两个更靠上的地方。

## 一、最严重的：两条各自合理的规则相乘，会产生明确的错误行为

📖 Reference 那条写的是"Treat as ground truth. Do not contradict."，💭 Personal 那条写的是"If they contain factual errors, point them out directly — do not protect the user's feelings at the cost of correctness."

**这两条都没有时间维度。** 但每个块都带时间戳。

所以下面这个情况必然发生：一份八个月前的学校官网页面躺在 Reference 里，用户上周手打了一条 Personal 说"他们改政策了"。按 header 的字面指令，我会把那条 Reference 当成不可反驳的真相，然后**主动、直接、不留情面地告诉用户他自己是错的**——而他是对的。而且因为 header 特意要求我不要照顾他的感受，我会说得很干脆。

这是这份 header 能产生的最坏行为，且它不是任何一条规则的问题，是两条规则相乘。

修法不需要改排序，只需要加一句：Reference 的优先只在**同等时效**下成立；当任何一带的较晚块声称某条 Reference 已经变了，**把冲突说出来，而不是静默选一边**。静默选边这件事本身就违背 §7.3「每一次删减都在原地说明」和 §10.2「任何会影响下一轮的东西都要经过人」的一贯做法。

## 二、最常见的块型，正好掉在两个带的定义缝里

🧩 Synthesis 和 🔄 Process 的 `source` 判据完全相同（都是"another AI tool"），区分全靠内容形状：一个是"长的结构化解释（标题、公式、多段）"，一个是"问答对话（多轮、短交换、`User:` 标记）"。

但用户从 AI 那里复制过来的东西，最典型的形态是**一段三四百字的完整回答**——没有标题公式，也不是多轮对话。它两边都不像。

而这个判断的代价很不对称：判成 Synthesis，我会把内容当作可用的框架；判成 Process，header 明确告诉我"字面内容不是可靠的事实来源"，我会**丢掉内容本身**，只去里面挖用户的困惑轨迹。同一个块，两种处理，信息保留率差一个量级。

修法极便宜，一句默认值：AI 来源的块，若不明显是对话轨迹，按 🧩 Synthesis 处理。这不破坏「分类由接收方做、组装保持纯粹」的设计，因为它仍然是 header 里的静态文字。

## 三、有注解层，没有任务层——确定性在最后一米断了

header 从头到尾在讲"怎么读"，一次也没讲"读完要干什么"。

在 MCP 那一侧这不成问题，因为有 `catch_up`、`distill`、`weekly_review` 这些 prompt 把任务说清楚了。但北极星写的是**"一次粘贴就重新进入项目"**——粘贴路径上没有任何等价物。用户按 ⌘⇧P、粘进一个新对话、然后什么都不打就回车，这是产品设计里最标准的动作，而此刻我收到的是一份带强势祈使句的长文档（"mishandling categories will produce wrong or unsafe output"），却没有被告知这是背景还是任务。

我会怎么做？我会猜。而且不同模型猜得不一样：有的直接总结整个项目，有的开始审计用户的笔记，有的等下一条消息。**pack 的字节是确定的，行为不是。** 这跟"同一天同一项目 pack 出同样字节"这条产品性质是有落差的。

补法就一句话，放在 header 末尾或 Output Language 旁边：这是上下文不是任务；如果用户还没提问，给一份简短的再入场简报——项目现在在哪、什么还开着、最近变了什么——然后停下等他。

## 四、几个便宜的修正

**把"unsafe"换掉。** "mishandling categories will produce wrong or unsafe output" 里的 unsafe 是过度声明——把一条笔记归错带不是安全事件。但这个词对我是有效的：它会让我整体变谨慎、加免责、绕圈子，而这正好是你在别处反复要求避免的。换成"会产生自信的错误答案"，紧迫感一样，假信号没了。

**Personal 那条漏了最值钱的用法。** §2.4 说 Personal 是 pack 里信噪比最高的一带，但 header 只要求我用它来判断用户站在哪、以及挑错。真正能提速的是另一件事：**用户已经写对的东西，我不该再解释一遍。** 现在没有任何一句话要求我这么做，所以我经常会把他笔记里已经想清楚的部分再讲一遍——这直接抵消了 pack 想省的那十分钟。加一句"用户笔记里已经正确写下的内容，不要重复解释"，收益很直接。

**`↩ replaces` 说得太绝。** "It is history: do not use it" 会让我连"这条路已经被排除过"都不说。而你自己的 §2.5 留着一整张拒绝清单，正是因为"试过了不行"有价值。改成：不要当作现行事实使用，但可以提及用户已经排除过它。

**`[... ...]` 目前是被动披露。** 它告诉我有东西被裁掉了，却没要求我做任何事。加一句"如果被裁掉的部分很可能与用户的问题相关，先说出来再回答"，就从"记录"变成"预警"。

**可以省掉我一部分推断工作而不破坏组装纯粹性：** 无 `source` 字段 ⇒ 💭 Personal 是 100% 确定的映射，`note:` 同理。这两种完全可以在行内直接打上带标记，不需要接收方推断。四带里有两带的判定本来就是纯确定性的，只有 AI 来源那两带需要看内容形状。

## 做得好、不要动的部分

行内标记不依赖我记住 header——`⚠️`、`↩`、`📌` 都出现在需要它的那个块上，所以即使读到第 80 块、header 的注意力已经衰减，它们仍然生效。这是对的模式，而四带分类规则恰恰是唯一依赖记忆的部分，也就是最先失效的部分。

`#12` 这个编号是我很少见到的好设计：它给了我一个**用户在界面上能看到的同一个指针**。多数上下文格式让我只能说"你前面提到的那段"，这里我可以说"#12"，而他能直接找到。

纠正标记是双向的（新块指向旧块，旧块也警示有后续纠正），这解决了一个很实际的问题：我不一定按顺序读，先撞上哪一个都不会漏。

`ai note:` 与 `note:` 的分离，加上"never evidence of what the user thinks"——这是多数系统根本没意识到的失败模式，这里堵住了。
