## 1. D3 `get_digest` — 跨脉络简报(R2 头号诉求)

**现状**:回答"我最近一周在忙什么"要 list_threads 后逐个 get_pack,R2 实测为最大摩擦点。

**接口**(新只读工具,工具面 8 → 9):

```
get_digest(workspace_title?: string, since_days?: int, max_chars?: int)
```

- `workspace_title`:限定一个工作区,名称大小写不敏感匹配(与 create_thread 同规则);
  不存在时报错并列出现有工作区名。缺省 = 全部工作区。
- `since_days`:活动窗口,默认 7,范围 1–90。
- `max_chars`:输出预算,默认 20,000,0 = 不限。

**输出**(确定性拼装的 Markdown 简报,非 JSON):

```
# Spool Digest: 全部工作区 · 自 2026-07-04(近 7 天)
Generated by Spool on 2026-07-10 14:00. 窗口内 3 条脉络有新块(共 11 条在库)。

## 近期活跃
### 〈工作区〉/〈脉络标题〉 — active · 45 块 · 最后活动 2026-07-10 09:12
summary: 〈目录卡一行〉
📌 [时间 · from 来源] 置顶块(≤600 字符,超出截断并标注)
[时间 · from 来源] 窗口内块,时间升序,每脉络配额 5(取最新 5 条)
    note: 用户批注(保留)
(+ 3 more blocks in window — get_pack / get_blocks 读全量)

## 其余脉络的置顶锚点(窗口内无新块)
- 〈脉络标题〉: 📌 〈80 字符首行锚点〉

——另有 N 条脉络无置顶且窗口内无活动(list_threads 查看全部)。
```

**行为规则(全部机械、可复述)**:

1. **时间窗**:cutoff = 本地自然日起点回退 `since_days-1` 天(即"近 7 天"含今天共 7 个
   自然日)。当日内同参数同输出(R3 明确要测确定性);代价是跨零点结果会变,属预期。
2. **排序**:脉络按窗口内最新块时间降序;脉络内置顶在前(创建时间升序),
   其后窗口内块时间升序(阅读序),并列以 rowid 决胜。全部确定性。
3. **配额**:每脉络窗口内块配额 5(取最新 5,渲染仍按时间升序);超出配额输出
   `(+ N more …)` 指路行。置顶不占配额、不受窗口限制(置顶 = 用户钦定的常驻核心)。
4. **每块字符帽**:600 字符,超出截断并加 `[... truncated, N more chars ...]`
   (深读走 get_pack / get_blocks —— digest 是广度工具,这是它与 get_pack 的边界)。
5. **超预算**:按 §2 排序装填,装不下的脉络整体降级为一行
   `〈标题〉(窗口内 N 块,未展开 — 预算所限)`;置顶锚点节同理逐行装填。
   预算行为内建于拼装,不存在"超限报错"路径 —— digest 恒定返回可用文本。
6. **来源标注**:块行完整保留 `· from 来源` 标签;不重复 get_pack 的四分类长表头,
   只在头部放一行指路:`Authority categories per get_pack's reading header; source labels preserved.`
7. **不内联附件文本**(哪怕 include_in_pack=1)—— 广度工具,附件深读属于 get_pack。
8. **空态**:窗口内无任何活动且无置顶 → 一行说明 + 建议(加大 since_days / list_threads)。

**合宪性**:只读;取舍规则全部机械(新近性、置顶、固定配额),服务端零 AI 判断
(宪法 4:确定性检索;宪法 5:AI 不替用户取舍内容 —— 配额与排序规则在输出头部
自我披露,模型和用户都能验算)。

**成本**:纯 mcp.rs 新增(digest 不是 GUI pack,不动 assemble.ts/golden);
cargo 单测:窗口边界、配额、预算装填、确定性(同库同参跑两遍字节一致)、空态、
workspace 匹配失败。instructions 工作流句同步提及。

## 2. D2 `add_block.ref_block_id` — 块级引用

**⚠️ 先纠错**:交接文档写"列已存在",实际 **schema v6 的 blocks 表没有 `ref_block_id`**
(只有 kind=ref 用的 `ref_thread_id`;PLAN §17 里 `ref_block_id` 是 v1.5 的架构钩子,
从未建过)。故 D2 需要 **schema v7**:

- 迁移 v6→7:`ALTER TABLE blocks ADD COLUMN ref_block_id TEXT`(加列、可空、幂等守卫,
  与 v5→6 同款);client.ts `SCHEMA_VERSION = 7`,mcp.rs `EXPECTED_SCHEMA_VERSION = 7`,
  锁步 cargo 测试自动覆盖。真库:动前备份(硬规则 3),首启注册表走迁移。
- 代价:v2.3(0.2.3)及更早构建按设计打不开迁移后的库 —— 与 v6 时相同,发布前可接受。
- 若 Ocean 否掉 D2,本轮完全零 schema 变更。

**接口**:`add_block` 增可选参数 `ref_block_id: string` —— 写入方声明"本块结论依据的
既有块"。写时校验:被引块存在、其所在脉络未软删,否则报错(错误信息指路 search_blocks)。
跨脉络引用允许(这正是价值:结论归档在 A 脉络,依据在 B 脉络)。写后不可改(append-only)。

**渲染**("↩ 依据"行,两渲染器 + golden):

- pack 内块的子行,位于 note: 行之后、附件行之前:
  `    ↩ cites: [2026-07-09 21:03] 〈被引块 40 字符首行锚点〉`
  (锚点复用现有 head_anchor;标记建议英文 `↩ cites: `,与 pack 全部英文标记一致
  —— §19.13;若 Ocean 要中文「↩ 依据:」照改,是常量一处。)
- 被引块已不存在(GUI 里块删除是硬删)→ `    ↩ cites: (cited block no longer exists)`。
- get_blocks JSON 行增 `ref_block_id` 字段;get_digest 的块行**不**渲染引用(广度工具)。
- GUI 块流**本轮不做**引用可视化(策展面的引用跳转是独立 UI 设计,另立章程;
  MCP 块的 Bot 徽章 + 批注已可辨识)。

**合宪性**:append-only 不破(引用是写入方自带的元数据,不触碰既有行);attributed
不破(引用块本身仍带 `· MCP` 前缀);宪法 4:引用渲染确定性。与 D1 呼应:给了正规
引用通道,"把 id 写进内容"就再无借口。

**成本**:schema v7 + assemble.ts/templates.ts + mcp.rs 双渲染器 + `GOLDEN_WRITE=1`
重生 golden(硬规则 5)+ PackDialog 侧给 assemble 喂被引块 map(GUI pack 也要渲染
引用行,改动限于装配数据层)。vitest + cargo 各补:有引/跨脉络引/悬空引三态。

## 3. C2 get_pack 预算式返回

**现状**:超 max_chars 只回统计 + 建议,一个字都不给([mcp.rs:1012-1033](../src-tauri/src/mcp.rs#L1012))。
R2 认为"给前 N 块完整内容 + 溢出说明"更可行动。

**行为**(仅改 MCP 侧超限分支,其余路径字节不变):

1. 骨架(标题块 + 四分类表头 + Output Language)与 **Pinned Blocks 节完整保留**;
2. Full Record **从最新块往回装**,整块为单位(块的全部子行含批注/附件提取一起计费),
   装到预算为止;被略去的 M 个最旧块在 Full Record **顶部**放一行:
   `[... M older blocks omitted for budget (~K chars) — get_blocks(offset=0, limit=M) 或加大 max_chars ...]`
   保留者仍按时间升序(时间线可读性不破);
3. Related Files & Links 只列被保留块的附件(与 range 过滤现行为一致);
4. 极端情形:骨架 + 置顶已超预算 → 退回现行统计 + 建议消息(此时部分渲染没有意义);
5. `max_chars=0` 不限、默认 50,000、空脉络/空窗口消息 —— 均不变。

**取舍说明**:交接建议"骨架 + Key Points 完整,Full Record 从最新往回装",此处
Key Points = Pinned Blocks 节,采纳;溢出说明放顶部是因为被略的是最旧块,读者顺读
时间线前先看到缺口声明。

**合宪性**:截断规则机械且在文内自我披露(宪法 4);不改变任何块内容。

**注意**:R3 附录回归项 1 的预期("返回统计+可行动建议")要改为"返回部分渲染 +
溢出说明;骨架与置顶完整"。落地后我把更新版 R3 提示词交给 Ocean(拍板点 4)。

**成本**:仅 mcp.rs(TS 渲染器与 golden 不动 —— 预算是 MCP 呈现层,不是 pack 格式);
cargo 测试:装填确定性、溢出行、置顶超预算退回、恰好等于全文长度(R3 边界项)。

## 4. C5 get_blocks 过滤(小,顺手)

**接口**:`get_blocks` 增三个可选过滤参数,AND 组合,作用于 offset/limit 分页:

- `pinned: boolean` — 只要置顶(或非置顶);
- `has_annotation: boolean` — 只要有(无)用户批注;
- `source_contains: string` — source 大小写不敏感子串匹配(如 "MCP"、"PDF";空串报错)。

**规则**:`total` 变为过滤后总数,响应回显生效的过滤条件;与 `around_block_id` 组合
**直接报错**("定位读上下文要的是真实邻域,过滤会造成假邻接")。
"无来源(=Personal)"过滤本轮不加 —— R3 若证明有需求,加 `sourceless: bool` 是一行事。

**合宪性**:只读、机械谓词。 **成本**:mcp.rs SQL WHERE 拼接 + cargo 测试。

## 5. D1 机制项

### 5a. `_ref` 改名 — **建议不做**(拍板点 5)

R2 的意思是把返回字段里的 `block_id`/`thread_id` 改名为 `*_ref` 一类,强化"这是
不透明句柄,别念给用户"。我的论证:

- **不改的理由**:(1) 入参名没法改 —— `thread_id` 是 8 个工具的既有参数名,只改出参
  会造成"读到 `thread_ref` 却要传 `thread_id`"的映射摩擦,模型每次调用都要跨这道坎;
  (2) 泄漏问题的根子已经在治:instructions 硬规则(R2 实测有效)+ 5b 的写入警告 +
  D2 的正规引用通道;(3) R3 在即,全量改名会churn整个field-tested工具面与 R3 提示词。
- **备选**(交接文档提的折中):仅新增字段用 `_ref` 后缀 —— 但同一工具面两套命名
  本身就是新的困惑源,不建议。
- 若 Ocean 仍要改,建议放到 R3 之后、发布前的独立批次,一次性改全并同步所有描述文本。

### 5b. add_block 疑似裸 ID 写入警告 — 做

**行为**:add_block 的 `content` / `annotation` 若匹配疑似 21 位 nanoid
(正则:nanoid 字母表 `[A-Za-z0-9_-]{21}`,两侧非字母表字符为界),照常写入
(**绝不拒绝、绝不改动内容**),但在返回 JSON 里附:

```
"warning": "content 中疑似包含内部 id(「sbC2zgTo…」)。请勿把内部 id 写进块内容——
引用其他块请用 ref_block_id 参数(或把 id 留在工具参数层)。"
```

附上匹配串(交接要求)。误报可能(随机 token、hash)—— 所以只警告。
**合宪性**:写入内容一字不动,警告是给写入方的教养提示,不是审查。
**成本**:mcp.rs 一个检测函数 + cargo 测试(命中/边界/误报形状)。
create_thread/set_thread_summary 如需同款是三行事,本轮按章程只做 add_block。

## 6. 缓办的两个效率项(本轮做掉,"彻底"要求)

### 6a. list_threads `approx_pack_chars` 改 GROUP BY 预聚合

现状 [mcp.rs:451-493](../src-tauri/src/mcp.rs#L451):每行 3 个相关子查询,
O(脉络数 × 块数)。改为两个 LEFT JOIN 聚合子查询(blocks 按 thread_id GROUP BY 出
count/pinned/字符和;attachments JOIN blocks 后按 thread_id GROUP BY 出内联附件和),
O(总块数) 一遍。

**等价性清单**(交接点名):软删过滤只在 threads/workspaces 层(blocks 无 deleted_at,
不受影响);每附件 `MIN(LENGTH(extracted_text), 8000)` 帽保留在 SUM 内;
`include_in_pack = 1 AND extracted_text IS NOT NULL` 条件保留;无块脉络 COALESCE 0。
**验证**:cargo 测试用种子库断言新查询与旧查询逐行相等(含空脉络、超 8k 附件)。

### 6b. search 短查询 snippet 复算

现状 [mcp.rs:581-610](../src-tauri/src/mcp.rs#L581):boundary 过滤时算一遍
snippet_around,渲染时再算一遍。改为过滤时算出即存入候选结构复用。
纯重构,零行为变化,现有测试覆盖。
