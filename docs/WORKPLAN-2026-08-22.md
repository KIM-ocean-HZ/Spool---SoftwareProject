### §2.D7 · 为什么"一键加回去"可能是解锁写入的钥匙

封锁写入的理由是：**它压得动的时候会丢日期，它不丢日期的时候等于没压，而两种结果长得一模一样。**
（实测：压完剩 91–101% 的那些一个数字都没丢；压到 64% 的那次丢了 5 个日期/数字，
含 CMU SCS 建议的 GRE 最晚重考日 `2026-11-25` —— **而那一档就叫「保留结论和数字」**。）

原来给的解法是**硬闸门**：丢了数字就不许存，只能**重跑**。
**Ocean 这条给的是第三条路，比重跑好** —— 丢了就**补回去**：
数字和它所在的那句话在原文里都还在，**这是纯本地、不花钱、不问模型的动作**。
补完就过闸了，不用等模型配合。

⚠️ **唯一的难点是插哪儿**（原句在压缩稿里可能已经被合并掉了）。**先想清楚再动手。**

### §2.F4 · 音视频开工前必须查的五条

**⛔ 查清再设计，不要先写代码。**

4. **云 ASR 能不能塞进 sidecar**，且**只收本地文件、不收 URL**（这样注入面不变）。
5. **B 站有没有能程序化拿到的字幕**。⚠️ "抓字幕就能覆盖视频"这个说法**已被收回**：B 站没有可选中的转录文本。

**四带归属（已定）**：对着麦克风说话 = **不带 source** = 💭 Personal（等于打字）；
视频/会议音频转录 = **必须带 source**（如 `Bilibili · 音频转录`），按来源判。
⚠️ 口述块要带一个「来自语音」的 **flag**（不是 source 标签）—— 理由很实在：
💭 那一带的规矩是"有事实错误就直接指出"，**转录噪声会被当成用户的主张，AI 会去纠正他根本没说过的话。**

| **「跑完了什么都没找到」要占住中间那一格** | 它是一个**结果**，不是没有结果。留一片空白，用户只能自己猜跑没跑、要不要再花一次钱 | `StaleReview.tsx` 的 `cleanRun` |
| **闸挡住的那几条必须整条带回来**（`StaleDropped`：两个编号 · 理由 · 两句引文 · 没过闸的是哪一步） | 只回一个数，界面手里就没有可给的东西，于是只能写「另有 1 条被丢掉了」—— 用户读到的是「**我的项目有问题，而 Spool 不告诉我**」。⚠️ 改回 `usize` **编译得过、测试也绿**（留下的那几条一条没变） | `api_engine.rs::gate_proposals` · `StaleReview.tsx` |
| ⛔ **「用户按了停下」必须和「子进程没起来」分开报**（`CANCELLED`） | 取消把子进程杀了，于是 stdout 是空的 —— 而「stdout 空」原来只有一种解释：装坏了。**结果是按一下停下，屏幕上叫你去重装 Spool。** ⚠️ 那一条判断**必须排在「stdout 是空的」前面**，排在后面就永远走不到 | `api_engine.rs::spawn_sidecar_with` |
| **停下之后桌子要回到「还没跑」，⛔ 不落 outcome** | 落进去就是在核对面上立一张红牌讲一件没发生的事故；⚠️ 自动重跑那一次被停下时**也不许把第一份端上桌**——他按了停下却冒出一份稿子，读起来就是「停下没起作用」 | `compressStore.ts::run` / `runCompress` |
| **说「停下了」⛔ 不许顺口说「没花钱」** | 已经吐出来的那一段，模型厂商那边照样算。⚠️ 而这个产品的信任全靠「测量记录」 | `compressStore.ts` 那句 toast |
