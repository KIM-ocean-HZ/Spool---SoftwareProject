### §2.D7 · 为什么"一键加回去"可能是解锁写入的钥匙

封锁写入的理由是：**它压得动的时候会丢日期，它不丢日期的时候等于没压，而两种结果长得一模一样。**
（实测：压完剩 91–101% 的那些一个数字都没丢；压到 64% 的那次丢了 5 个日期/数字，
含 CMU SCS 建议的 GRE 最晚重考日 `2026-11-25` —— **而那一档就叫「保留结论和数字」**。）

原来给的解法是**硬闸门**：丢了数字就不许存，只能**重跑**。
**Ocean 这条给的是第三条路，比重跑好** —— 丢了就**补回去**：
数字和它所在的那句话在原文里都还在，**这是纯本地、不花钱、不问模型的动作**。
补完就过闸了，不用等模型配合。

⚠️ **唯一的难点是插哪儿**（原句在压缩稿里可能已经被合并掉了）。**先想清楚再动手。**

### §2.E3 · 作废检测接产品之前

⛔ **key 先挪进钥匙串。** 现在是"单独一个文件、0600、不进 settings.json、不跟着导出的库走"——
**这是个够用的临时方案，不是终点**。当时的目的是先让 Ocean 看见压缩质量。
⛔ **接任何写入之前必须挪。**

⛔ **永远不要把 sidecar 的依赖挪进 `src-tauri/Cargo.toml`。**
"主进程不发网络请求"之所以还能说，是因为**外人能当场验**：

```bash
cd src-tauri && cargo tree -e normal | grep -iE "ureq|rustls|reqwest|hyper|openssl"   # 必须是空的
```

把 HTTP 库塞进主 crate、只是"放着不调用"，这句话就从**架构性质**降级成**意图承诺**。

**实测判定（60 次，6 份 pack）**：指到不相干的块 **0/39**；三个从没测过的项目 **15 次全部输出 `[]`**，
而每一份里都埋着 1–2 个"像真的"的陷阱 —— **它守规矩，而且是在有诱惑的时候守的。**
⚠️ **但失败形状不是"指错块"，是"看对了、动作提错了"**：39 条里 35 条是"同一件事、旧块还剩很多"，
用户点了同意会让一个**内容仍然有效**的块退出以后每一份 pack。**所以界面必须问"合并/只退旧的/不动"，不能问"要不要作废"。**

⚠️ **召回只有一对真值撑着**（5 次里 4 次找到 = 80%），**而且补不齐 —— 库里就只有这一对。**
