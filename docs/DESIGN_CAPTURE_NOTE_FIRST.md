# 捕捉重构:双击 ⌥ 之后直接写批注(note-first)+ 砍掉收集面板

2026-07-31。Ocean 提出、授权「审查通过即动手」;本文是审查结论 + 实现记录,
供 Ocean 复核。**如对结论有异议,回滚点是本批次的提交。**

## 0. Ocean 的原始想法

1. Spool 专注的是**用户的个人思考**,但双击 ⌥ 只把剪贴板搬进去,想留一句自己的话
   (note)还要再点两下——不利于养成「任何信息都留 note」的习惯。
   想要:双击 ⌥ 弹出 toast 后**自动进入 note 输入框**,直接打字零摩擦,
   点击外部 = 不留 note。
2. 如果快捷 note 成立,**收集面板(长按 ⌥)是不是可以整个不要了**?
   它不够简洁,而且能被「连续双击」替代。
3. 顺带:收集面板里单击 ⌥ 的行为不稳定——有时放大缩小,有时直接加块。

## 1. 审查结论:两条都通过,附三个修正

### 1.1 note-first 成立,而且大半机制已存在

现在的 toast **本来就有批注编辑器**(双击 toast 正文展开、自动聚焦、失焦保存、
Esc 取消、各条 dismiss 路径都会 flush 草稿)。改动本质只有两件:

- toast 出现时**默认就展开批注框**,并且**捕捉浮窗主动拿键盘焦点**
  (今天是刻意不拿——`focus:false` + 弹出后把焦点还给来源 app);
- 所有关闭路径把焦点**还给来源 app**(还焦点的机制 `reactivate_app_async`
  已存在,只是今天在弹出时用,现在挪到关闭时用)。

**代价要说清楚**:双击 ⌥ 之后紧接着的键盘输入会进 note 框,而不是用户原来的
编辑器。这正是 note-first 的本意(邀请你写一句想法),但对「双击完继续在原 app
打字」的肌肉记忆是个行为变化。缓解:

| 用户想干什么 | 动作 | 结果 |
|---|---|---|
| 留一句话 | 直接打字 → **Enter** | 存为该块批注,toast 关,焦点回到原 app |
| 换行(长 note) | Shift+Enter | 正常换行,「完成」/Enter 提交 |
| 不留 note | 点外部任意处 / Esc | toast 关、无 note、焦点回原 app |
| 连续摘录 | 回原文选下一段(这一下点击本身就是「点外部」) | 上一条自动收尾,毫无额外成本 |
| 什么都不做 | 置之不理 | 8 秒后自动关(框里没字才会自动关),焦点归还 |

### 1.2 修正一:点外部时**框里有字就保存**,空才是「无笔记」

Ocean 说「点击外部即代表无笔记」——按字面实现会把已敲的字扔掉。
捕捉工具丢用户打过的字比多存一条批注严重得多(且撤销/改批注都容易)。
所以:**点外部 = 空框不存、非空保存**。「无笔记」的含义落在「不打字直接走」上。

### 1.3 修正二:收集面板砍掉,判定为**结构性缺陷**而非 bug

单击 ⌥ 行为不稳的根因(读 double_tap.rs 状态机可证):

- 单击「结算窗」300ms < 双击判定窗 500ms。两次间隔 300–500ms 的「单击」,
  第一击先触发了缩放,第二击又和第一击配成了「双击」→ 直接加块。
- 双击加块还受 copy-gate 约束(10 秒内有过 ⌘C 才算捕捉),收集时通常刚复制过,
  所以「有时加块、有时缩放」随打字节奏和复制时机漂移。

这不是实现错误,是**三种手势(单击/双击/长按)挤在同一个键上、时间窗又互相
重叠**的必然歧义。任何修法都是在窗与窗之间挪毫秒,换一批新歧义。

而它的独特价值——「批量摘录后合成一块」——在 note-first 下有完整替代:
连续双击捕捉(见上表「连续摘录」行,零额外成本),回主窗多选合并
(MergeToolbar 已有);且每段还能带各自的 note,来源比合成一大块更清楚。

**结论:整个收集面板(长按 ⌥ + 单击 ⌥ 缩放 + 暂存合并)删除。**
双击 ⌥ 成为唯一手势,一个手势一个结果。官网从未宣传过收集面板,无对外文案孤儿。

### 1.4 修正三:自动消失的判定改为「框里没字才自动关」

现在「展开批注 = 暂停自动消失」;note-first 下 toast 永远是展开态,照旧就永远
不自动关。改为:**框里空且无悬停 → 8 秒自动关;打了字 → 不自动关**(Enter/点外部收尾)。

## 3. 实机验证结论(2026-07-31,隔离 identifier `com.oceanjin.spool.nf`,已拆干净)

隔离构建无任何 TCC 授权 → tap 落在 `session/listen-only`,合成事件可见,
故可脚本驱动。真库全程未被触碰(前后 sha256 逐字节一致)。

| 场景 | 结果 |
|---|---|
| 双击 ⌥ → 浮窗出现,**光标已在批注框** | ✅ 截图与打字均证实(`set_focus` 对 `focus:false` 窗口可靠) |
| 打字 → Enter | ✅ 块 + 批注「this is the thought I had」同时落库,浮窗关闭 |
| 打字 → Esc | ✅ 块落库,`annotation` 为 NULL(草稿按设计丢弃) |
| 打字 → 点浮窗外部 | ✅ 批注「kept on click away」保留(修正一生效) |
| 不打字、放着不管 | ✅ 8 秒自动消失,无批注 |
| 干净安装英文种子 | ✅ 12 块,含新的「Leave a note」教程行 |
| MCP 二进制(删 collect.rs 后回归) | ✅ initialize + 10 工具 |

**没验到的三项,必须 Ocean 真手指测**:

1. **焦点归还来源 app**。隔离构建没有输入监听权限,tap 只看得见 Spool 自己的事件,
   所以合成触发时 Spool 必须在前台 → `prev_source_app` 恒为 "Spool" → 按设计不做
   activate,这条分支跑不到。
2. **中文输入法**里 Enter/Esc 不误触发(`isImeComposing` 需真 IME)。
3. **正式版(HID/active)路径**下的整套行为 —— 见下面这条新发现。

### ⚠️ 新发现:装了正式版之后,合成事件再也测不了手势

两个授权齐全时 tap 装在 **HID 层**,而 `CGEventPost` 注入的事件进的是 session 层,
**HID tap 完全看不见**(实测:连 `1st-of-pair` 都不打)。§5.2 当初能合成触发,
是因为那个隔离构建没授权、tap 退到了 session/listen-only。

**结论**:凡要验证正式版上的手势,只能真手指按;脚本验证一律走无授权的隔离
identifier。已记进 memory `double-tap-exclusivity`。
