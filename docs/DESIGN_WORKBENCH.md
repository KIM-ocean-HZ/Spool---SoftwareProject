## 1. 先说那个真 bug,因为它改变了问题的性质

### 1.1 「没有新增块」不是 AI 没干活,是 Spool 把答案扔了

Ocean 问:8/6 14:32 生成周回顾没有新增块,14:34 提炼结论没有新增块,为什么?

**答案:AI 两次都干完了活。Spool 收到了完整的产出,然后删掉了正文,只报了个块数。**

链条是这样的:

1. 三个动作的提示词里都写着同一句话 ——「**先把结论念给用户听,他同意之后,
   再用 add_block 存回**」(`mcp.rs` 的 `distill_prompt_text` / `weekly_review_prompt_text`
   / `thread_health_prompt_text`)。
2. 这句话是给**有人在旁边聊天**的场合写的(Claude Desktop):AI 说一遍 → 用户说「好」
   → 它才写。
3. 但 Spool 自己跑引擎是 **`claude -p` 无人值守**。**没有任何人能说那句「好」。**
   所以模型完全按规矩办事:把整篇周回顾、整块结论写进它的**最终回答**,一块都不写。
4. 那段回答顺利传回 —— `run_action` 返回 `env.result`,`ai_engine_run` 原样交给 JS,
   `engineStore.pump()` 拿到它,存进局部变量 `resultText`。
5. **然后除了 `follow_up_brief` 以外,全部直接丢掉。** 只剩一句 toast:
   「跑完了,没有新增块」。

排除掉的可能:Ocean 的「允许 AI 写入」是**开着的**(查过 settings.json,
`mcpWriteEnabled: true`),不是写入闸门的问题。

### 1.2 为什么这条值得单独立一节

因为它**推翻了 Ocean 那条结论的前提**。

他说:「都已经使用 ai 引擎了,ai 的行为却简单的说没有新增块 …… 会让用户认为 ai
什么也没做」,所以「我倾向于 ai 维护自动化」。

诊断对,药方的**顺序**要调:**一条会把自己产出丢掉的流水线,自动化之后
只会变成「每周安静地烧一次 token,你还是什么都看不到」。**
先让产出看得见,再谈自动跑 —— 这也是本稿 §4 的阶段顺序。

### 1.3 顺带,这解释了「AI 维护」为什么一直感觉是空的

三个动作里有两个(提炼结论、整理去重)的设计产出**就是一段话**,不是一块。
`DESIGN_AI_ENGINE.md` 把它们的价值寄托在「先念给用户听」上,
**却从来没有给「念」这个动作准备一块地方**。`follow_up_brief` 是唯一有面板接着的,
所以也是唯一感觉起作用的 —— 这不是巧合。

## 3. 右侧栏:形状

### 3.0 为什么是右侧栏,而不是再加几个弹窗

VSCode 敢让插件动你的代码,是因为 **Source Control 面板让你看得见它动了什么**。
这句话在 `HANDOFF.md` §4.7 里已经躺了很久,当时的结论是「AI 活动面」——
做出来是主视图里一个折叠区。**那个折叠区是对的方向,但位置不对**:
它长在某一个项目的正文流里,而引擎的事有一半根本不属于任何单个项目
(周回顾、待审队列、花费总额、引擎本身)。

右侧栏解决的是同一件事,但给了它**一个和内容平级的容器**,而不是内容里的一个夹层。

### 3.1 第一格:AI 说了什么(这是 §1.1 那个 bug 的落点)

每次跑完,右侧栏出现一条:

```
提炼结论 · Flux 项目 · 刚刚 · Claude Code (opus) · $0.03
──────────────────────────────────────────────
到今天为止,这个项目定下来的是……
（AI 的完整正文,可展开可折叠）
──────────────────────────────────────────────
[ 存成一块 ]  [ 不用了 ]
```

三件事同时解决:
- **正文留下来了** —— 这是 §1.1 的修复。
- **「先念给用户听,他同意才写」这条设计规则终于有了「同意」的地方。**
  原来无人值守跑,那个「同意」在物理上不存在;现在它就是那个按钮。
  ⚠️ 这一条很关键:**提示词一个字都不用改**,它一直是对的,缺的是接盘的 UI。
- **花费和模型就在同一行**,回答 Ocean 的 #5。

### 3.2 第二格:动作(把三个按键从 ⋯ 菜单里搬出来)

⋯ 菜单里那组「让 AI 维护」整体搬到右侧栏。理由不只是「更显眼」:
菜单是**点开就消失**的东西,而这些动作要跑几分钟、有排队、能取消、有产出 ——
它们需要一个**待得住**的地方。取消按钮也一起搬,不再是标题栏一颗认不出来的药丸。

⚠️ **保留 ⋯ 菜单里的入口** —— 已经习惯的路不要断,但它不再是唯一的路。

### 3.3 第三格:待你过目(▤ 角标搬家)

Ocean 要两件事:
1. **不要那么隐蔽** —— 搬进右侧栏,常驻显示(有 0 条的时候写「没有待过目的」,
   而不是整块消失)。
2. **每个项目内部能看到自己最新的 follow-up 消息,点击即可选择** ——
   右侧栏跟着当前项目走:打开 Flux 项目,这一格只显示 Flux 的待审提案。

⚠️ **他说的「消息弹窗」不能照字面做。** memory `capture-note-first` 有一条铁律:
**主窗永不跳前**。提案是 AI 在用户可能睡着的时候排进来的,一个会抢焦点的弹窗
直接违反那条铁律。折中:右侧栏那一格**变色 + 计数**,窗口回到前台时才有动效 ——
看得见,但不抢。

### 3.4 第四格:回顾(周回顾从项目菜单里挪出来)

拍板(Ocean 2026-08-06):**自动建一个「回顾」项目**。

- 周回顾**不再出现在任何项目的 ⋯ 菜单里** —— 它是全库动作,放在项目菜单里
  从一开始就是错的(`lib.rs` 传 `{}` 就是这个错的证据)。
- 入口在右侧栏这一格,以及自动触发(§4.3)。
- 产出**追加进一个 Spool 自建的「回顾」项目**,一次一块。
  这样它「有独立性」(Ocean 的要求),同时**留在库里** —— 以后能被搜到、
  能打包给 AI 看、跨周能对比。
- ⚠️ **建这个项目的时机是「第一次真的生成回顾时」,不是安装时。**
  memory `spool-db-wipe-incident` 那条红线:**任何 seed 逻辑都不许碰已有的库**。
  这里是「用户触发的一次 create_thread」,不是 seed,但时机上必须写死,
  免得以后有人把它挪进启动路径。

### 3.5 第五格:引擎(把 MCP 设置页拆开)

Ocean #2 的病根:MCP 设置页上并排放着**两件根本不同的事**:

| | 是什么 | 用户的心智 |
|---|---|---|
| **接出去** | 把 Spool 的库接给外面的 AI 客户端(6 个一键接入 + 配置片段) | 「我在别处聊天,想让它读到我的笔记」 |
| **请进来** | 让本机的 CLI 替我跑维护动作(检测、选引擎、超时) | 「我想让 AI 替我整理这个项目」 |

它们共用「MCP」这个词,但用户要做的决定完全不同。加上 Gemini CLI 只会更乱
(Ocean 预见到了)。

**拆:设置页保留「接出去」那一半(它本来就是设置);
「请进来」那一半整体搬进右侧栏的引擎格** —— 引擎选择、模型、effort、花费,
都在你**正要用它**的地方,而不是在一个要专门去打开的设置页里。

设置页只留一行指路:「AI 引擎的设置在右侧栏 →」。

### 3.6 等待过程要有变化(Ocean #11)

现在的结构决定了这件事做不到:`output_with_timeout` 是**等子进程整个跑完**
才读它的 stdout。中途拿不到任何东西,所以界面只能是静止的。

两个 CLI 都能边跑边吐:
- **codex**:`--json` 本来就是逐行 JSONL,现在已经在传了 —— 只是被攒到最后才解析。
- **claude**:`--output-format stream-json`(+`--include-partial-messages`)。

要做的是把运行路径从「攒完再读」改成「边读边发事件」,右侧栏显示
「正在查第 2 条:xxx」。⚠️ **这一步风险最高**:改 claude 的输出格式会动到
现在唯一验证过能跑通的解析路径。所以它排在最后(§4 阶段四),
而且**必须真机跑一次**(`HANDOFF.md` §6.2-ter 的教训:子进程的活,单测全绿也可能三个动作全是坏的)。

## 4. 阶段划分(每阶段可独立验证)

### 4.1 阶段一:地基 —— 让产出活下来 ✅ 已落地(2026-08-06 深夜)

没有这一层,右侧栏里没有东西可显示。

- **schema v12:`engine_runs` 表**。字段:动作、项目(周回顾为 NULL)、引擎、模型、
  结果状态、**AI 的正文**、花费、token 数、起止时间。
- ⚠️ 这**扩展了** `HANDOFF.md` §3.5 那条「Follow up 区域 = 推导视图,不建表」。
  理由:那条说的是跟进**状态**(能从块和 brief 推出来);而 AI 的正文
  **没有任何地方可以推导** —— 它现在的唯一副本在一个局部变量里,函数返回就没了。
- Rust 侧解析 `total_cost_usd` / `modelUsage`(§5)。
- `engineStore` 不再丢弃正文。

**验证**:`npx tsc --noEmit` / `npx vitest run` / `cargo test` 三条全绿;
迁移在真库副本上跑一遍,**行数逐项一致**(§6.3 的换装规矩)。

### 4.2 阶段二:右侧栏本体 ✅ 已落地(2026-08-06 深夜)

外壳(左右都可拖宽/收起,学 VSCode)+ §3.1–3.5 五格内容。

**验证**:⚠️ **装完必须截图看窗口**(`HANDOFF.md` §6.2-bis:
`tsc` 干净 + 测试全绿 + 签名全过,主窗照样能白屏)。
⚠️ 特别盯 zustand selector:**`selectAllThreadsFlat` 绝不能当 hook selector**。

### 4.3 阶段三:自动化 + 动作重排 —— ✅ 前两项已落地(2026-08-06 深夜)

拍板(Ocean 2026-08-06):**只在项目真变了才跑**。

- 「变了」= 这个项目自上次成功维护以来**新增过块**。
  ⚠️ **可推导,不加列**:`engine_runs` 里该项目最后一次成功的 `finished_at`,
  对比该项目最新块的 `created_at`。没动过的项目**一次都不跑**。
- 一个总开关 + 每个项目能单独关(Ocean:「让用户放心并且有开关」)。
- 周回顾挪进「回顾」项目(§3.4)。
- 模型 / effort 选择(§5)。

⚠️ **省 token 是硬要求,不是「顺便」**。Ocean 原话:「必须节约token」。
每一条自动触发规则都要能回答「这次跑为什么值这个钱」。

### 4.4 阶段四:流式进度

§3.6。**风险最高、必须真机跑**,所以最后做。

## 5. 额度 / 模型 / effort:能拿到什么(2026-08-06 实测)

全部用**不花额度**的办法探出来的(`HANDOFF.md` §6.2-quater 那两招)。

| 想要的 | 能不能 | 怎么拿 |
|---|---|---|
| **这次跑花了多少钱** | ✅ | claude 的 JSON 信封里**本来就带** `total_cost_usd`。⚠️ **Spool 现在就收到了,只是没解析** —— `RunEnvelope` 只读三个字段,其余被 serde 静默丢弃 |
| **用了什么模型、多少 token** | ✅ | 同上,`modelUsage` |
| **选模型** | ✅ | 两个 CLI 都有 `--model` |
| **选 effort** | ✅ | codex:`-c model_reasoning_effort=…`。**用假键对照法验过是真键**(报错只提假键),没花额度 |
| **账号还剩多少额度** | ❌ | 两个 CLI 都不在无人值守模式下报。claude 的 `/usage` 是交互式的 |

**所以对用户能说的最诚实的话是**:
> 「这次花了 $0.03,Spool 这周一共花了 $0.41」

**能显示花了多少,不能显示还剩多少。** ⚠️ 别在 UI 上暗示后者。

⚠️ codex 侧的花费字段**还没探**(它的 JSONL 事件流里在哪、叫什么都未知)。
探它不需要花额度 —— 但需要一次能跑通的运行,而 codex 额度 **9/4 才恢复**。
在那之前 codex 的花费列显示「—」,不要瞎猜字段名。

## 6. 顺手要修的小东西

### 6.1 引擎选择器显示的是代号,不是产品名

`McpConfig.tsx` 的 `<option>` 里写的是 `{e.kind}`,渲染出来是 `claude` / `codex`。
`ENGINE_LABEL` 这张表就在 `engineStore.ts` 里放着没用上,它给的是
`Claude Code` / `Codex`。

### 6.2 CMU 那个例子换掉(Ocean #10)

**两处都要换**:
1. `FollowUpPanel.tsx` 输入框的 placeholder。
2. `mcp.rs` 里 `follow_up_brief_prompt_text` 的正文 —— 中英两侧都有。

换成所有用户都可能遇到的。候选(要挑一个**具体到能当搜索规则**的,
这正是那个例子存在的意义):
- 「我在用的这个工具/库有没有出新版本、有没有破坏性改动」
- 「我盯的这个东西涨价没有、政策变没变」

⚠️ 别换成更抽象的 —— 原来那条 CMU 例子**形状是对的**(具体、可执行),
只是题材小众。Ocean 要的是换题材,不是换形状。

### 6.3 「一键接入」的登录报错还是英文原话

`HANDOFF.md` §3.1 留下的,没动:CLI 没登录时的报错原样透传到 toast。
codex 那侧已经会透传自己的原话(「额度用完了,9/4 再来」),claude 那侧该补句人话。

## 7. notes 当标题(Ocean #13)—— 部分采纳

Ocean 的观察很准:「blocks 大部分都是 compact 之后或者给 MCP 看的,用户其实看的少,
真正需要显示出来的信息可能是用户的 notes」。

**但直接照做会坏**:`BlockItem.tsx` 自己的注释里写着
「most blocks (which won't have annotations)」—— **多数块根本没有批注**。
把批注提成标题,多数块会顶着一行空白,正文还被降级成小字。

**建议的形状:有批注的才当标题。**
- 有批注 → 批注在上,大字/标题态;原文缩到下面,小字。
- 没批注 → **保持现状**,一个字不动。

### 9.6 ⏸ 他直接问的一个问题:「提炼出来的内容有什么用?」

**诚实的回答:今天他的感受是对的 —— 因为它的产出一直没有落点。**

`distill` 的设计定位在 `DESIGN_MCP_WRITE_ROLE.md` §2.1 那张表里:
它**不是**「总结全文」(那一格判的是 ❌ 别写,可推导),
它是「**推导很贵、结论很稳**」的那一种 —— 花了大力气才得出的一句话,存回去。

**它真正的价值不是给人看的总结,是让下一次的 pack 变短但不变差**:
一句提炼过的结论,替代了十块散落的过程。这是 §2 那条「上下文卫生」的原生形态。

**但它今天拿不到这个价值,有两个原因:**
1. **产出以前被扔掉**(§1.1 的 bug,08-06 才修);他用的那两次正好在修之前。
2. **提炼出来的结论回到库里之后,跟原来那十块并排躺着** —— 库变长了,没变短。
   ⚠️ **缺的正是「取代」** —— `DESIGN_CONTEXT_HYGIENE.md` §3.1。
   提炼的结论应该能说「我取代了 #3 #7 #11」,那十块就退出 pack 正文。

**→ 所以「提炼有什么用」这个问题的答案,是那份稿子的第 2 件事。**
⚠️ **在取代关系落地之前,不要为了让它「显得有用」而给它加功能** ——
它缺的不是功能,是出口。

### 9.8 ⭐ 他同时问的:「压缩应该把所有块都压一遍吗?还是只留一块?」

**两个都不对,而且第一个是红线。**

**① 全部压一遍 —— 永远不做。**
那等于把用户的原话换成 AI 的转述。三条,任何一条单独都足够否掉它:
- **块不能改**(append-only),这是「允许 AI 写入」那个开关敢打开的全部理由;
- **用户 capture 的文字是标准**,这是产品的立身之本;
- **压错了看不出来** —— 原始表达一旦没了就再也回不来。

**② 只留一块 —— 就是今天的行为,而它正是「压缩」这个名字兑现不了的原因。**
产出一条结论,**原来那十块还在**。库变长了,不是变短了。

**③ 正确的形状:压缩 = 一条结论 ➕ 一份「它取代了哪几块」的清单。**
用户批准 → 那几块**退出 pack 正文,但留在库里**(还能搜、还能查)。
**净效果才是「压缩」** —— 加一条,减十条。

⚠️ **一个值得记下来的发现**:按 `DESIGN_MCP_WRITE_ROLE.md` §2 那道
「可推导性」闸门,「把已有的块总结一遍」本来就是判 ❌ 的
——**今天的「提炼结论」其实一直踩在那道闸门上**,只是靠「推导很贵」这条例外放行。
**加上「取代」之后它才真正合规**:它不再是"多一份摘要",是"换一种表示"。

**两条硬约束(落地时别漏):**
1. ⚠️ **pin 过的块、有批注的块,压缩一律不许碰。**
   那是用户亲手给的显著性信号(`DESIGN_CONTEXT_HYGIENE.md` §2.2),
   而这三样正是 Spool 相对整个行业的结构性优势。压掉它们等于把自己的长处删了。
2. ⚠️ **只压「过程」,不压「事实」。** 十块讨论怎么选方案 → 压成「选了 A,因为 B」对;
   十块是十份不同的官方通知 → **一块都不许压**。

⏸ **所以「压缩」这个名字今天是半个承诺** —— 它对,但要等取代关系(`DESIGN_CONTEXT_HYGIENE.md`
§3.1 / 交接 §3 的 **H2**)落地才兑现。**改名不等于改行为,这一窗只改了名。**

### 9.10 ⚠️ 模型选择为什么只有 claude 一半(W3-c)

**claude:能选,而且是问出来的不是猜的。**
`claude --help` 自己写着别名用法("an alias for the latest model (e.g. 'sonnet' or 'opus')"),
`--model haiku` **真跑过一次**(2026-08-07,~$0.02),信封回来的 `modelUsage` key 是
`claude-haiku-4-5-20251001`。所以给的是**别名**(opus / sonnet / haiku),不是钉死的 id ——
别名跟着账号走,钉死的 id 等模型退役那天就烂了。默认是「默认」,意思是**根本不传 `--model`**,
Spool 不去覆盖用户在别处设好的选择。

**codex:今天给不了,而且这是个测量结果。**
两条,任何一条单独都足够:
1. 它的模型是**服务端下发的目录**(0.146.1 二进制里是 `model_catalog_json` /
   `supportedReasoningEfforts` / `defaultReasoningEffort`),不是编译进去的常量;
2. **它不在本地校验 `-c` 的值** —— 拿 `model_reasoning_effort="bogus-effort"` 试过
   (2026-08-07),CLI 照单全收,还在开跑横幅上原样打印出来。

合起来的后果:猜一个名字**不会当场报错**,会等用户等完一次运行之后在 API 那头失败。
所以宁可不给选,UI 上直说「等 9/4 额度回来再测」。补它需要**一次能跑完的 codex 运行**。

### 9.11 ⚠️ 顺手堵上的一个洞:claude 那边一直在加载用户自己的 MCP 服务器

探流式的时候看见的:一次运行的 `system/init` 行里,列着**另一个库**的工具 ——
Spool 传了 `--mcp-config`,但没传 `--strict-mcp-config`,所以用户 `~/.claude` 里配的
MCP 服务器**全都跟着进来了**。

⚠️ **这不是安全洞**(`--allowedTools` 白名单照样拒掉它们),**是钱**:
每次运行都要把一堆用不上的工具定义塞进上下文,按 token 计费。Ocean 那句
「**必须节约token**」正好管这个。codex 那边从 §7.3 起就有对应的 `--ignore-user-config`,
claude 这边现在补上了。**真机核过**:补完之后 init 行里只剩 Spool 自己的 14 个工具,
`permission_denials: []`。

### 9.12 ⚠️ 项目管理区:第一版做错了(Ocean 2026-08-07 当天推翻)

**我做的第一版**:右侧栏顶部一格,**默认折叠**,收起时写「N 个项目在进行」。

> 且**没有占据位置,用户并不会使用**」

两条都对,而且第二条推翻了我那个折衷的全部理由:
**一个折叠起来的盘点面板,等于没有这个面板。**

**✅ 他给的正确形状(2026-08-07 拍板,已落地):**

| 在哪 | 是什么 |
|---|---|
| **左侧栏置顶** | 一个叫「**项目管理**」的**总项目**,**显示方式和普通项目一样**,只是置顶 |

  开着项目管理 → 全库那半边。**同一个面板不再同时讲两个范围。**
- **矩阵终于排得下。** 左右两栏分别只有 280 / 250px,`可以做成矩阵排列` 在里面**物理上做不到**;
  中间区是全 app 唯一够宽的地方。
- **占了位置。** 它是一个要点开的视图,不是一行折叠标题。

⚠️ **两条被这一版推翻的旧结论,别照旧稿做:**
1. **§9.4 原来那条「它不是第二个导航,一旦能打开项目就是冗余」——** 现在**点卡片就是要跳转**
   (Ocean 明示)。那条警告是写给「它长在右侧栏」的版本的;
   现在它**本身就是从左侧栏进去的**,一张点不开的卡片才是死路。
2. **「总结项目」去掉** —— Ocean 原话「**总结项目去掉,没有用**」。
   压缩留在它该在的地方:被压的那个项目自己的右侧栏。

**落地位置**:`src/components/ProjectBoard/index.tsx`(矩阵)、
`src/components/RightRail/BoardRail.tsx`(它的右侧栏)、
`threadsStore.boardOpen`(哪一侧在前台)、`src/lib/threads/deadline.ts`(DDL 天数,两处共用)。

⚠️ **`boardOpen` 是个 flag,不是一个假的 `activeId`。** `loadAll` 会把「对不上任何一行的
activeId」清掉,所以塞一个假 id 进去每次刷新都会被悄悄重置;而且每一个读 activeId 的地方
(块加载、捕捉目标、打包)都得学会跳过它。选中的项目在底下原样留着,从矩阵退出来还在原处。

⚠️ **`dueInDays` 比的是「日历天」,不是「过了多少毫秒」。** 截止日期存的是那天的最后一刻,
直接相减再取整,**在真正到期的那天会显示「还有 1 天」**,`0` 只在过期那一瞬间出现 ——
「今天到期」永远不会被看到。这条有测试盯着(`deadline.test.ts`),而且**换个时区也得过**。

## 9.13 第三轮反馈:UIUX 全面返工(Ocean 2026-08-07,又亲手用过之后)

### 9.13.0 先说被推翻的:「上下文卫生」往后排

上一窗的交接把 `DESIGN_CONTEXT_HYGIENE` 定成主线。**Ocean 明示先不做**,
理由就是上面那句 —— 界面不过关之前,往里加功能是把问题埋深。
那一摊没有取消,只是排在这一轮 UI 返工之后。

### 9.13.1 跟进删不掉(第 1 条)—— 是两个 bug,不是一个

原话「**跟进没法删除,也不会消失**」。拆开:

| 症状 | 真因 | 修法 |
|---|---|---|
| 删不掉 | `RunCard` 的按钮区包在 `!answered && outcome === 'ok' && hasText` 里。**跟进产出的是待审提案,不是正文**,所以常常 `hasText === false` —— 整张卡一个按钮都不渲染 | ✕ 提到卡片标题行,**无条件渲染** |
| 不会消失 | 点过「不用了」只是把卡片变灰,**永远留在栏里**,而且只增不减 | `reviewedAt !== null` 的卡片**直接不显示**(`lib/engine/activity.ts` `visibleRuns`,有测试) |

⚠️ **数据库那一行不删。** 它是近 7 天花费统计的依据,删了总数就说谎了。
「消失」只是不在面板上,不是不存在。

### 9.13.2 项目汇总彻底离开右侧栏(第 2、5 条)

上一窗把「项目管理」做成了左侧栏置顶项 —— 这一半是对的。错的是**右侧栏还留了个 `BoardRail`**
(周回顾 + 自动维护总开关)。Ocean 第二次说同一件事:「**去掉项目汇总的右边栏**」。

**现在:开着项目管理时,右侧栏根本不挂载。** 中间区吃掉整个宽度。
周回顾和自动维护总开关搬进项目管理自己的工作区,就在它们管的那张列表上面。
`BoardRail.tsx` 已删除。

### 9.13.3 右侧栏重做(第 5 条)

原话:「**矩形结构太多,没有空间呼吸感。按钮很大很长不美观,不够简洁,尤其是不够直觉性
……做了过多了隐藏抽拉的设计,看似简洁,实则摩擦巨大**」。

三件事:

1. **折叠全拆了。**「让 AI 维护这个项目」原来是个折叠三角,挡在两个按钮前面 —— 每次多一次点击,
   挡的还是这个面板存在的理由。现在是**钉在底边的一行**,永远看得见。
   ⚠️ 只留了一个折叠:最底下「这个项目里有 N 块是 AI 写的」。它是**查阅**材料不是动作,
   而且展开长度没有上限。
2. **不再有整栏宽的带框按钮。** 一列这种东西读起来像表单不像面板。动作是**图标 + 两个字**,
   共用一行,靠留白而不是边框分隔。
3. **空的东西不占像素。**「没有待过目的」原来是一个永远在那儿、永远点不动的灰框。现在 0 条就不渲染。

### 9.13.4 那个谁也看不懂的按钮(第 4 条)

原话:「**这个项目:跟着总开关走(点一下单独关掉)—— 我自己都没看懂这个按钮,太有歧义了,
并且用户根本不知道这里能点击**」。

两个毛病是同一个毛病:**它是一句话在假装自己是个控件**。
现在是**带标签的开关**(和设置页同一个 `Toggle` 组件),长得就是它该有的样子。

⚠️ 而且**只在总开关打开时才出现** —— 自动维护关着的时候,没有任何东西会自动跑,
一个「单独关掉」的开关是在控制一个不存在的东西。

### 9.13.5 Claude Code 的 effort(第 3 条)—— ⚠️ 机制做完了,选择器没上,因为实测不通

原话「**Claude code 模型为什么没有 effort。加进去**」。查下来两层:

**第一层:没有 `--effort` 参数,所以找不到是正常的。** `claude --help`(2.0.50)里没有这一项。
控制是有的,只是走**环境变量** —— 从装着的那个二进制里读出来的解析顺序:

```js
let T = process.env.CLAUDE_CODE_EFFORT_LEVEL;
if (T) { if (T === "unset") return; …; if (["low","medium","high"].includes(T)) return T }
```

**第二层(2026-08-07 真跑测出来的,这才是关键):这一版 CLI 够得着的模型全都不支持它。**

```
CLAUDE_CODE_EFFORT_LEVEL=low claude -p "…" --model haiku
  → API Error: 400 "This model does not support the effort parameter."
  --model sonnet  → 同样的 400
  不带 --model    → 同样的 400   ← 账号默认也逃不掉
  --model opus    → 404 "model: claude-opus-4-1-20250805"   ← 另一个 bug,见下
把环境变量去掉,同一条命令返回 OK,花费 $0.035。
```

⚠️ **所以变量不是「被忽略」——CLI 会把它转发上去,是 API 那头拒绝。**
今天把选择器放出去,等于**每一次运行都失败**。这正是 §2.2 给 codex 模型定的那条规矩:
**宁可不给选**。

**落地状态:管道全通、有测试,界面开关关着。**
`EngineBar.tsx` 的 `EFFORT_PICKER_ENABLED = false` 一行就能开回来。
修在 CLI 那边不在 Spool 这边 —— effort 要 Opus 4.5+ / Sonnet 4.6+,而这一版把
`sonnet`、`opus` 映射到更老的快照。**`claude` 升级之后重测一次。**

⚠️ **顺手测出来的第二件事:`opus` 这个别名在这台机器上本来就是坏的**(404,
指向 `claude-opus-4-1-20250805`)。模型选择器现在提供 opus/sonnet/haiku 三个,
**选 opus 会直接失败**。这跟 effort 无关,是一个独立的、之前没人测过的洞。
→ **Ocean 08-07 晚拍板:整个模型选择器撤掉,见 §9.13.10。**

### 9.13.7 项目管理重做:卡片变成会展开的行(第 7 条)

- **删除**走 `threadsStore.remove`,和左侧栏同一条软删除 + 撤销吐司,**⌘Z 能捡回来**。

### 9.13.8 一键问 AI —— ⚠️ 三个设想里只有一个能做,另外两个说清为什么不能
