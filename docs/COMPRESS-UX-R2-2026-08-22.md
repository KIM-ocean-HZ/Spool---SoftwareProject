## 1. 压缩稿直接替换原库正文（⭐ 最大的一条）

**原话**：「不行，复制入库摩擦太大，需要用户一个一个 block 删除、添加，直接让用户自己审核、
替换原库文字；但是未压缩的原库需要备份保存，默认备份，用户可关，这样的话如果 MCP 使用库时
遇到错乱的逻辑，可以申请去看原库的对应内容……被压缩的 block 带一个 compressed 的标签，
用户可以回 spool 拿到原始信息。保留原库、一一对应还有一个好处：新加入的 block 可以被单独压缩，
压过一次下次就不会再被压缩，只能被检测语义是否废除。」

⛔ **这一条明说推翻了「库里一个字都不动」那条锁。** 锁是他定的，也只有他能解 —— 他解了。
⚠️ 但**数字硬闸门（D-b）不动**：丢了数字/日期的压缩稿仍然不许写进库，先「加回去」补齐。

### ✅ 拍板了：原文跟着块走

一块自己带着压缩前的原文，同一个库里。**好处**：天然一一对应，永远不会错位；
MCP 只看一块就能拿到那一块的原文；导出、备份、换机器都跟着走。
**代价**：库大约 1.8 倍（只是磁盘，不进 pack）。

⛔ 另外两种都被否了：整库快照（**做不到一一对应** —— 压缩会合并、会重编号）、
新建压缩块让旧块退居二线（块数翻倍，界面到处要写「这块已被替代」）。

### 要做的事

| | 做什么 | 注意 |
|---|---|---|
| **1a** | 块上加两样：**压缩前的原文** + **压过的时间** | 库版本号 +1（现在 23）。⚠️ 迁移要能回滚 |
| **1b** | 核对面上加「**用这一份**」 | ⛔ 数字闸门先过；⛔ 一次一块地看得见改了什么（那正是 §2 和 §3 做完的事） |
| **1c** | 设置：**默认备份原文，可以关** | ⚠️ 关掉 = 压缩不可逆，界面上必须当场说清楚，不能只写在设置里 |
| **1d** | 压过的块**带标签**，pack 里认得出来 | 渲染器已经有 `🗜`。⚠️ 表头在 TS 和 Rust 各写一遍，`byte-identical` 测试盯着 |
| **1e** | **只压新块**：组压缩用的 pack 时跳过已经压过的 | ⭐ 这条同时解决了「重复花钱」和「压过的又被压一遍」 |
| **1f** | MCP 能**按需取一块的原文** | ⚠️ 加工具要同时改路由文本 + 写 `annotations`（两条护栏，各自都被漏过一次）。pack 里**不带原文** —— 让 AI 主动问 |
| **1g** | 一键还原 | ⭐ 原文还在，还原是白拿的。⛔ 不做还原就等于让 AI 产物盖掉用户的字 |

## 2. ✅ 按字对，不是按段

**原话**：「删除和新加的文字大部分都是重复的，需要对比的是真正变化的文字，而不是变化的段落，
做到让用户一看就知道哪些文字在被压缩后的 block 中消失了，哪些文字是原来没有的，
AI 压缩的语义逻辑没有问题，重要的是关键信息也没有丢失。」

✅ 做完了：先按行对齐 → 同一处的删行和加行按相似度配对（= 同一句被改写）→ 配上的**按字**对一遍。
配不上的才是真的整行删了 / 真的整行新写的。
⚠️ 被改写的那一行**不走 markdown 渲染**：渲染器会吃掉 `**` 和 `==`，字和字就对不上了。

## 3. ✅ 指到句子上；加回去要看得见

**原话**：「根本看不到丢掉的数字是哪一块的，即使文字说 #2，我也不知道 #2 写了什么，
需要指到文字内容上去；并且更严重的问题，加回去用户根本看不到这个动作，不知道到底加在哪里。」

✅ 做完了：卡片上直接列出那句话的原文，后面跟它自己的「加回去」；补回去的那一行在右栏
当场标出来，写着「你加回去的」。
⚠️ 后半条是真的会漏：补回去的行和原文一模一样，LCS 会把它当成「没变过」——**不特意标就看不见**。

## 4. ✅ 整理工作区（项目内切页签）

✅ **做完了（`db35a5d`）**：项目里多一排「内容 / 整理」页签；整理状态按项目存；
核对面那个 X 撤了（出口是页签，要扔改成明写的「不要这一份」）；右栏按钮只负责把你送过去。
⚠️ 压缩没开的时候整条页签不出现。

**原话**：「右边栏的压缩这个项目按钮交互逻辑不好……1. 点击退出压缩工作区就无法回去；
2. 进入一个项目的压缩面板之后，就无法访问其他项目的 block 内容；……我的想法是把每个项目的
工作区和压缩工作区绑定，可以在工作区内切换浏览压缩和内容页，这样的话每个项目的压缩互不干扰，
后续的作废都可以放进现在的压缩工作区，统一一个名字。」

### ✅ 定下来的形状

```
项目《申请规划》
  内容 | 整理(1)
  ═════
```

- 「整理」页签里放**压缩核对**，以后**作废建议**也进同一个页签；
- 切回「内容」永远回得去 —— ⛔ 现在那个「关掉就找不回来」的死路没了；
- 每个项目各有各的整理状态，**互不干扰**；
- 点左栏别的项目 → 到那个项目的「内容」，它自己的整理状态原样留着。

## 5. 批注根本不发给 AI

**原话**：「禁止批注被 AI 修改，直接不发送批注就行，发送给压缩时选定正文部分发送，
甚至可以把字数多的 pack 切割，多次压缩来提高准确率；含有替代关系和引用关系的文字
可以用映射关系来确保压缩不会碰到被引用的内容。」
配套那句（第 6 条末尾）：「**除了数字丢了（可以自动加回去）之外，其他警告 100% 禁止发生。**」

⭐ **这条是把「求模型守规矩」换成「结构上做不到」。** 现在核对面报的六类警告里，
有五类（批注少了 / 批注被改写 / 编了批注 / 高亮没了 / 引用关系断了）**根源都是同一件事：
那些字被送出去了**。不送就不可能被改。

| | 做什么 | 注意 |
|---|---|---|
| **5a** | 送去压缩的 pack **摘掉批注、高亮标记、引用/替代行**，压完按映射原样放回 | ⚠️ 占位符要选一个模型不会改的形状，而且**放回失败必须报出来**，不能静默 |
| **5b** | 长 pack **切批**，分几次压 | ⚠️ 切批会让跨块合并的机会变少（压缩率下降），也可能更贵。**这是取舍，要量过再定切多大** |
| **5c** | 核对面那五类警告降级 | ⛔ 别删掉检查 —— 检查是最后一道网。改的是「它不该再发生」，不是「不再看」 |
