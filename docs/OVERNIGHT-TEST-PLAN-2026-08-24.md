### 阶段 2b 🆕 · U14/U15：按下停下之后，产品说的是哪一句（3 次）

⭐ **这一格是 U14 唯一的真实验收。** 和阶段 2 是同一个道理：离线能证明**判断的顺序**对，
证明不了**真的把一个正在联网的子进程杀掉之后，走到的是哪一条分支**。
而 U14 修的就是这件事 —— 修之前，Ocean 按一下「停下」，屏幕上叫他**去重装 Spool**。

**病根**（`api_engine.rs::spawn_sidecar_with`）：取消把子进程杀了，于是 stdout 是空的，
而「stdout 空」原来**只有一种解释**（子进程死在产出信封之前 = 装坏了）。
修法是 `CANCELLED` 标志，⚠️ **而且必须排在「stdout 是空的」前面**，排在后面永远走不到。

**做法**：拿申请规划那份 pack 起一次压缩，**另起一个线程等 5 秒之后调 `compress_cancel()`**，
连做 3 次。⭐ `compress_cancel()` 是个不带参数的 `pub fn`（`api_engine.rs:427`），
测试里直接调得到 —— ⛔ 不用去点界面，也不用起 GUI。

✅ **实测台已经加好了（2026-08-23 23:27），不用再动代码。** `Step` 上多了一个字段：

```jsonc
{ "label":"取消-申请规划", "thread":"", "pack_file":"…/texts/pack-申请规划-all.txt",
  "range":"all", "level":"balanced", "reasoning":"low", "repeats":3,
  "cancel_after_secs": 5 }          // 0 或不写 = 不取消，跑法和以前一模一样
```

发出去 `N` 秒之后，另一个线程调 `compress_cancel()`。⚠️ **那个线程是 join 过的** ——
不 join 的话，一条迟到的取消会飘到**下一步**去（正常跑完之后 `CHILD` 里那个已退出的子进程
还在，`CANCELLED` 会被立起来，而下一次 spawn 开头才清）。⛔ 那条缝就是「上一步取消了下一步」。
