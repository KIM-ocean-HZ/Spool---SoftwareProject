## 1. Ocean 的三条要求,和它们各自的病根

原话照抄(HANDOFF §2.7 H-5):

> 「MCP 端做不到 prompt 提示,只有 claude code 可以,但是主要 MCP 还是 GPT、claude desktop
> 这些,所以 MCP 的使用 prompt 指引需要更加清晰且零摩擦:①不能让用户自己在网页和 APP 中
> 零散地去拼凑 MCP 使用方式;②不能让用户自己去问 AI『spool 能干什么』;③不能让用户使用
> MCP 之后自己都不清楚 AI 在调用什么工具(因为用户看到的是 prompt 名称,而用户不一定知道
> prompt 是做什么的)。」

| 要求 | 现在实际是什么样 | 病根 |
|---|---|---|
| ① 不用自己拼凑 | 用法散在三处:官网 MCP 段、app 设置里的「复制使用提示」、教程种子的最后一块。三处说法不一样,教程那句还停在旧版 | 没有「唯一一份用法」 |
| ② 不用自己问「能干什么」 | 用户接上之后,对话框是空的。他要么什么都不问,要么先问一句「你能读我的 Spool 吗」 | 第一轮对话里没有任何提示 |
| ③ 看得见 AI 在调什么 | 客户端只显示工具名(`get_pack`)和返回的 JSON。用户看不懂 | 返回值是给模型看的,没有一句给人看的 |

**注意:③ 说的「prompt 名称」,在 H-2 落地之后已经变成「工具名称」** —— 三个 prompt
现在同时是工具了。问题一样:`distill` 这个词对用户毫无意义。

## 3. 每一条怎么做

### 3.1 决定 1 —— 工具返回第一行用大白话说「我刚做了什么」

**长什么样**(用户在客户端里看到的第一行):

```
读了〈机器学习课〉的完整简报:17 块,其中置顶 3 块,附件正文 1 份。
# Project Context: 机器学习课
...
```

```
在全库搜「验证曲线」,23 条命中,这里给你前 20 条。
{ "query": "验证曲线", ... }
```

```
体检了〈机器学习课〉:3 处疑似重复、1 处悬空引用、1 处正文里露出的内部编号。
```

**⚠️ 一个真问题,要你知道**:`get_pack` 的返回是**用户要原样粘给别的 AI 的东西**。
在它前面加一行,粘出去的时候就多了一行不属于 pack 的话。

三个选项:

| | 做法 | 好处 | 坏处 |
|---|---|---|---|
| a | **除 get_pack 外都加**(建议) | pack 一个字节不动,其余七个工具都有人话 | get_pack 恰恰是最常调的那个,它还是没有人话 |
| b | 全都加,pack 那一行放在 `---` 分隔线之后 | 一致 | 用户复制时容易连着复制走 |
| c | 全都不加 | 零风险 | ③ 这条就没解决 |

我建议 **a**。理由:pack 有自己的标题行(`# Project Context: 机器学习课`),
用户看到那一行已经知道 AI 读的是哪个项目;而 `search_blocks` / `get_blocks` /
`check_library` 这些返回的是纯 JSON,那才是真正一个字都看不懂的地方。

**成本**:每个工具一句 `format!`,约 40 行,不动任何返回结构。

### 3.2 决定 2 —— `initialize` 开头加三句「你可以直接这样说」

服务器的 `initialize` instructions 是**每个客户端都会读的唯一一处**(Claude Desktop、
ChatGPT、Cursor、Claude Code 全都读)。现在它开头是身份行 + 一整段给模型的工作规则,
里面没有一句「用户会怎么说话」。

**加什么**(放在身份行之后、工作规则之前):

```
The user talks to you in plain language, not tool names. Typical openers, and what to
call:
  "我最近在忙什么" / "这周干了啥"        → get_digest, then weekly_review
  "机器学习课我卡在哪" / "我定下来了什么" → search_blocks → get_pack, or distill
  "把这条存回去" / "帮我记住"            → add_block (ask which project first)
If this is your first turn with Spool connected and the user has not asked anything
specific, say in one sentence what you can now do for them, using their own project
titles — call list_threads first so the examples are real.
```

**为什么这能解决 ②**:模型在第一轮就会主动说「我现在能看到你的 Spool,你可以问我
『最近在忙什么』,或者让我看某个具体项目」——而且**用的是他自己的项目名**,不是抽象说明。
用户不需要开口问「你能干什么」。

⚠️ 这段是英文,和现有 instructions 一致(§19.13:模型跟英文指令更稳)。

### 3.3 决定 3 —— 用法只维护一处

现在三处各写一份,而且已经开始互相打架。建议:

**唯一一份 = app 设置里那段可复制的开场白**(现在的「复制使用提示」)。理由:
- 它是唯一一个**用户接完就在眼前**的地方(接入按钮就在旁边);
- 它是**可复制的**,用户可以直接粘进客户端的 project instructions;
- 官网和 README 是给还没装的人看的,不该承担「怎么用」。

**要改的**:
- 现在那段是**给 AI 读的工作规则**(「用 list_threads 了解我的项目」……),
  不是给人看的。**改写成一段既能粘给 AI、人读了也懂的开场白**,并把三句示例问法放进去。
- 官网 MCP 段 → 只说「装好后在设置里点一下就接上,里面有一段可复制的开场白」,不再自己列用法。
- README 同上。
- 教程种子最后那块 → 见决定 4。

⚠️ **官网文案改了要重跑 `node scripts/build-site-zh.mjs`**(硬规则 4)。

### 3.4 决定 4 —— 教程种子里那句过时的话

现在:「一键接入 Claude Desktop / Cursor」。实际支持六个(Claude Desktop、Claude Code、
Cursor、Visual Studio Code、Windsurf、ChatGPT / Codex)。

改成不点名的说法:「设置 → MCP,一键接上你在用的 AI 客户端」。
**不要在种子里列客户端名字**——列了就要跟着维护,而且商标那条(§5.6)说贴 logo 不安全,
文字点名虽然安全但一样会过期。

⚠️ 5/29 红线:种子只进空库重建路径,**存量库永不播种**。改了种子,Ocean 自己的库不会变。

## 4. 做完之后怎么验(验收标准)

拿实验室 + Claude Code 走一遍:

1. 新开一个对话,**什么都不说**,只问「你现在能帮我做什么」→ 模型应该用**真实项目标题**
   举例,而不是背工具清单。(验决定 2)
2. 说「我最近在忙什么」→ 工具返回第一行应该是人话,说清它读了什么。(验决定 1)
3. 全程不提任何工具名、不点任何菜单,把「查一个项目 → 存一条结论」走完。
   中间**一次都不需要用户知道 MCP 术语**。(验 ①②③ 合起来)

## 5. 明确不做的,和理由

- **弹窗 / 新手蒙层**:§2.5「安静」。而且引导发生在**别的软件里**(Claude Desktop),
  app 内弹窗根本管不到那边。
- **app 内放一个「MCP 教学页」**:又多一处要维护的用法,和决定 3 正好相反。
- **给每个工具起中文名**:工具名是给模型看的,改中文会让模型更难对上英文的用户意图。
  ③ 要解决的是「用户看不懂」,答案是第一行人话,不是改名。
