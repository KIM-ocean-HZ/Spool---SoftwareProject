## 1. 环境发生了什么变化

**2026-08-18，企业微信 5.0.10 正式对所有规模企业开放 CLI 与 MCP。** 消息、邮件、文档、表格、
智能表格、智能文档、待办、日程、会议、微盘、通讯录共 11 类核心办公能力，直接开放给外部
AI Agent；取消了此前的企业人数与资质门槛。官方 `wecom-cli`（Rust，WecomTeam 组织开源）能读
会议纪要与转写原文。安全侧叠加了原有权限与审批：AI 操作权限独立配置、关键动作人工审批、
授权有有效期到期自动回收、所有调用可追溯。

**这件事对 Spool 的三层含义：**

1. **"给企业微信做中转"这个位置，腾讯自己占了。** 再去写一遍企业微信 API 对接，既打不过官方，
   也撞穿零出网红线——何况那条路本来就走不通：2022-06 起新建自建应用必须配置可信 IP 白名单，
   一个动态 IP 上的本地桌面应用拿不到入场券。
2. **但腾讯放出来的是"动作能力"，不是"跨天记忆"。** wecom-cli 能读文档、建日程、拉纪要，
   它不回答"这个项目三周前为什么否掉了方案 A"。而且企业微信的 AI 授权是按次审批、到期回收的
   通道，天然不是项目日志。
3. **那一层是空的，而 Spool 正好是那个形状**：四带权威模型 + append-only 日志 + 确定性 pack。

## 2. 定位结论：不做工作版

**结论：不做"工作版"，做"和办公软件并排装的项目记忆层"。**

一句话定位：**给 AI Agent 用的项目记忆层，装在你公司的办公软件旁边**——而不是"一款办公软件"。

### 2.1 反对做工作版的三条硬证据

| # | 证据 | 含义 |
|---|---|---|
| 1 | 至少在 8/18 开放前的版本里，授权了 CLI 能力的企业微信机器人**限制仅创建者可对话**，其他成员不可使用 | 连腾讯自己都把 Agent 接入定位成个人生产力工具。做"分享共创"是在生态位上逆行 |
| 2 | 通讯录 >1000 人的企业，"可配置长连接接入的成员"**默认为空**，需管理员逐个开通 | 阻力不在 UI，在 IT 后台。产品设计解决不了 |
| 3 | 分享共创要账号、服务器、同步 | 一次性反转零出网、无账号、"MCP 是唯一 AI 通道"，外加已在拒绝清单上的实时协作，换来和企业微信智能文档正面竞争 |

### 2.2 对"从业者反馈"的重新解读

> 原话大意：Spool 确实方便，但中国市场已被企业微信/钉钉占据，员工每天固定打开这些 app，
> 很难有理由再用一个更私人化的东西。

**前半段成立，结论下反了。** Spool 的接触点从来不是"打开 app"，是双击 ⌥ 和 ⌘⇧P。
这两个动作不跟企业微信抢时间，所以不需要抢。

### 2.3 一个应该前置的定位反转

**零出网在中国企业环境里不是包袱，是最强的过审论据。** 很多公司明令禁止内部数据外传，
Spool 是唯一一个"装了也不会往外发一个字节"的东西。配合 §15.2 里"一次性买断 + 离线签名许可证"
的形状，恰好是采购最容易签字的组合。反倒是工作版——要账号、要同步、要上传——最难过审。

> ⚠️ 这条论据与 §5 的 API 引擎有直接张力，见 [§5.4](#54-对定位论据的影响必须同步改的表述)。

## 3. 七条办公软件接口的裁决

| # | 原设想 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 日程/待办承接 | **放弃读取方向** | 企业微信"获取日历下的日程列表"仅可获取**应用自己创建的日历**下的日程；手动创建的日历，日程接口无法识别。读用户已有日程在技术上封死 |
| 2 | 公司云盘 | **不做对接** | 已有 attachment extraction + per-file `ai_access`。该做的是让 Agent 把云盘文件的摘录存进 Spool——这是 routing text 的事，不是新管道 |
| 3 | 智能文档承接 | **做** | 唯一零红线成本的一条。pack 已是纯字符串组装，加一层输出模板（pack → 适合 Agent 写进智能文档的结构）。§16.2 已把 workspace pack → folder 列为现成的缝 |
| 4 | 公司 API 是主战场 | **做，见 §5** | 比原判断更强：§12.2 已测出免费额度撑不起维护引擎（20 请求/天 vs 设计假设 1500，差 75×），Gemini 免费层已关 |
| 5 | 分享共创 | **不做** | 见 §2.1 |
| 6 | 蓝白色调专业办公 UI | **不做** | 收益不可验证，且与"Classic appearance IS the shipped app"冲突。办公场景认的是审计痕迹（AI 写入强制来源标签、纠正是提案不是覆盖），这些已经有了，缺的是用企业听得懂的话讲出来 |
| 7 | 语音会议纪要中转 | **降级为 routing text** | wecom-cli 已能读会议纪要与转写原文。Spool 不需要碰语音，只需让 Agent 知道"纪要读完归档到哪个项目"。与第 3 条是同一件事的两端 |

**必须区分清楚的一个坑：** DeepSeek Harness 不走 engine slot。它是本地部署、浏览器访问的 Web
应用，原生 skills 支持，MCP 需改配置启用，**目前不支持 CLI 命令行**。所以 dsh 接 Spool 走的是
MCP 方向（它当 client 连 stdio server），不是 §9 的引擎槽。搞混会白做一轮。

## 4. 产品方向：三条强化线

### 4.0 先说瓶颈的真名

"不知道往哪强化"不是想象力不够，是**手上没有回答这个问题所需的信息**。§2.6 的功能过滤器是一条
停止规则，它现在正常工作，告诉你的是：**没有东西可以再为"你这一个用户"建了**。§2.2 写着没做过
用户调研，§16.3 第四条张力写着"一个用户被深度服务十三周，是合格的 v1 方法、不合格的 v2 方法"。

**所以宣传不是第二件事，是解锁第一件事的前提。** 顺序搞反，就会在零外部信号下继续凭直觉加功能。

### 4.1 把 provenance graph 浮上来 —— 优先级最高

- **依据**：§16.2 写着 `cites` / `supersedes` / `corrects` 已经在数据里、"几乎没有被呈现"；
  §16.1 把权威模型排在最难被复制的第一位。**最强的资产目前只活在 pack 的静态表头里。**
- **做什么**：v0.6.1 的纠正折叠（纠正钉在被纠正的句子下面、虚线连接）已经开了个头。推到
  "这个结论踩在哪几块上、其中哪一块已经被纠正过"；MCP 加一个只读工具暴露引用关系。
- **第一步动哪个文件**：时间线渲染器 + MCP 工具表（记得 §8.4：新工具必须同时出现在 `OPENERS`
  或 `INSTRUCTION_BODY`，否则第三方客户端永远不会调用它；且必须声明 `annotations`）。
- **红线成本**：零。

### 4.2 按自己测出来的数据调头

- **依据**：§12.2 —— 一个真实项目的 pack 里，**95% 的体积来自人粘贴文档，AI 写入只占 5%，
  且块大小小 11 倍**。
- **两个推论**：①"AI 写入会淹没库"已被证伪，**该扩大 AI 写入面而不是收缩**；
  ② 真正的容量敌人是大段粘贴，所以抽取、范围选择、folder pack 才是打在实处的。
- **红线成本**：零。

### 4.3 第一天的价值

产品价值需要积累才显现，这是最大的转化障碍。这条同时是产品方向和转化方案，细节见 §6.3 / §6.4。

### 4.4 明确不做

**Linux、移动端、E2EE 同步。** 在有第二个用户之前是纯投机；而且 §11.3 自己写了 Linux 的捕获
触发与焦点处理是重写不是移植。

## 5. AI 压缩重启与国产 API 接入

**Owner 的要求（2026-08-19）**：重启 AI 压缩功能；加入国产 API（DeepSeek 等）的快捷操作。

### 5.1 这件事撞上了哪些红线

| 红线 / 事实 | 出处 | 是否被撞 |
|---|---|---|
| "MCP is the only AI channel — all built-in AI removed (Gemini/Groq/Ollama)"，2026-07-09 | §13 | **是**（若主进程直连） |
| "Zero egress from the app itself"，2026-07-09；CSP 结构性禁止网络请求 | §13 / §0 事实 1 | **是**（若主进程直连） |
| "Spool never becomes a network client... **No API key is stored, entered or needed**" | §9 引擎槽三性质之一 | **是**（三种形态都撞） |
| "Pack is pure string assembly，AI never in the hot path" | 原则 4 | 否，只要压缩是**额外产物** |
| "Every cut is stated in place，Nothing is silently summarised away" | §7.3 | **有风险**，见 §5.3 |

> §13 的规矩：红线只能由 owner **明确**反转，**绝不能作为实现别的东西的副作用**被推倒。
> 因此下面三种形态必须先选定，再动代码。

### 5.2 三种实现形态

#### 形态 A — 主进程直接调 API
- **得到**：体验最顺，一个设置项就能用。
- **代价**：CSP 要开口子；"永不发出网络请求"从**架构性质**降级为**意图承诺**；网站、README、
  案例研究全部要改；§2.3 那条最强的过审论据直接作废；§10.2 的注入链条要重画（app 自己成为
  网络客户端后，pack 内容直接出站）。
- **判断：不建议。** 代价远大于收益。

#### 形态 B — engine slot 加一个 OpenAI 兼容 CLI
- **得到**：零红线成本。§16.2 明说"第四个引擎是填槽，不是架构变更"。
- **代价**：用户要先自己装一个 CLI，转化差；DeepSeek 官方目前没有 CLI。
- **判断**：作为**并行**选项保留——Qwen Code 支持 MCP / Skills / 子智能体，且可用阿里云百炼
  Token Plan（含团队版）API Key 配置，凭证由 Qwen Code 自己管，Spool 只 spawn 子进程，
  与 claude / codex / gemini 完全同构，**不需要反转任何红线**。适合已有 CLI 的用户。

#### 形态 C — 随 Spool 分发的 sidecar 子进程 ⭐ 推荐
- **做法**：Tauri sidecar。Spool spawn 它，**它**才是网络客户端。§10.1 的出站表格里已经有这一行了
  （`CLI engine | Spool spawns a local subprocess | That CLI, on the user's login and quota`）；
  形态 C 只是把"用户自己装的 CLI"换成"我们自带的最小二进制"。
- **复用**：§9 的 detection / streaming / cost parsing / sandboxing / 每次运行时限全部复用。
- **只需反转一条红线**：§9 的 "No API key is stored, entered or needed"。key 由 Spool 的设置界面
  收集。**这一条必须由 owner 明确点头，不能作为副作用发生。**
- **主进程 CSP 不动。** "Spool 自身不发出任何网络请求"字面上仍然成立。

### 5.3 无论选哪种形态，都必须遵守的设计约束

1. **压缩产物是额外输出，永不替换确定性 pack。** 原则 4 说 pack 是纯字符串组装、AI 不在热路径。
   压缩版必须与原版并存，原版始终一键可达。
2. **压缩产物必须自报家门。** 沿用 §8.3 的强制来源标签（`DeepSeek · API` 之类），客户端不可设置。
3. **压缩必须说出自己压掉了什么。** §7.3 的 "Every cut is stated in place" 是这个产品最好的性质
   之一；AI 压缩天然会静默摘要，这是**重启这个功能最容易破坏的东西**。压缩产物顶部必须写明
   原始块数、压缩后块数、被合并/省略了哪些。
4. **失败必须可见。** §12.3 的教训："唯一症状是沉默的失败"是这个项目最怕的一类 bug。
   API 超时、余额不足、限流，都要在界面上说出来，不能退回未压缩版本而不告诉用户。
5. **默认关闭。** 与 MCP 一样，是第二个独立开关。

### 5.4 对定位论据的影响：必须同步改的表述

形态 C 之下，对外说法要从"永不联网"精确化为：

> **Spool 主进程不发出任何网络请求。当你打开 API 引擎时，请求由 Spool 启动的本地子进程发出，
> 用你自己的 key 和额度，内容到达你选择的那家模型厂商。**

§10.4 已经有"deliberately not claimed"这一节，加一行即可。**不要因为不好讲就不讲**——
§10.4 的存在本身就是这个产品的可信度来源。

### 5.5 成本模型（为什么现在做是对的）

**DeepSeek 新价目（2026-08-17 生效），单位：元/百万 tokens，顺序为 缓存命中输入 / 未命中输入 / 输出：**

| 模型 | 空闲时段 | 高峰时段 |
|---|---|---|
| V4-Flash | 0.05 / 1.5 / 4.5 | 0.10 / 3 / 9 |
| V4-Pro | 0.15 / 4.5 / 13.5 | 0.30 / 9 / 27 |

高峰时段为北京时间每日 **9:00–12:00、14:00–18:00**，闲时价格为高峰的一半。V4 系列支持百万级
上下文，**同时兼容 OpenAI 与 Anthropic 两种调用格式**（接入成本因此很低）。

**一次满额 pack 压缩的成本估算**：pack 上限 50,000 字符。按官方换算（1 中文字符 ≈ 0.6 token）
取最坏情况约 30,000 tokens 输入 + 2,000 tokens 输出：

- V4-Flash 高峰、缓存未命中：≈ **0.11 元**
- V4-Flash 闲时、缓存未命中：≈ **0.055 元**

对照 §12.2 记录的"一次实时 web 运行 ≈ $0.45（约 3.2 元）"，**差约 30 倍**。这就是"经济学变了"
的具体数字，值得写进案例账本。

**两个由此产生的、别人做不了的功能：**

- ⚠️⚠️ **这一行的 50 倍是错的，2026-08-20 回查官方价目更正为 30 倍。**
  0.10 vs 3、0.05 vs 1.5、0.30 vs 9、0.15 vs 4.5 —— **四个格子的比值全是 30**。
  而且 30 倍只属于输入，输出不打折。**正确的算法在 `WORKPLAN-2026-08-20.md` §6.2，
  以那一份为准，别从这里抄数字。**
- ~~**确定性 × 缓存 = 50 倍降价。** 缓存命中价比未命中便宜约 50 倍（Flash 0.05–0.10 vs 1.5–3）。~~
  而 pack 是确定性的——同一项目在同一天 pack 出同样的字节。**前缀天然稳定，重复压缩同一项目
  几乎必然命中缓存。** 原则 4 的确定性在这里直接换成了钱。这是竞品做不到的，因为他们的 pack
  每次都不一样。
- **错峰运行。** 高峰时段正好覆盖上班时间。周回顾、项目总结这类任务本来就可批处理，
  加一个"闲时运行"开关直接省一半。也没有别人能做，因为别人的任务不可延迟。

### 5.6 实施顺序建议

1. Owner 明确选定形态（推荐 C），并明确反转 §9 "不需要 API key" 这一条，记入 §13。
2. 先做 **`compress_pack` 一个动作**，不要一次上齐周回顾/项目总结。这是验证形态 C 的最小切片。
3. 设置界面：厂商预设（DeepSeek V4-Flash / V4-Pro、Qwen 等）+ 自定义 OpenAI 兼容端点 + key +
   闲时运行开关 + 单次运行成本显示（§9 已有 cost parsing）。
4. 跑通后再把 weekly review / distill 迁到同一个引擎。
5. 案例账本追加一行：压缩成本实测 vs 估算。**这个项目的传统是用测量推翻假设，别在这里破例。**

## 6. 转化漏斗：发布前必须补的五件事

> 渠道修好了只会把更多人送进同一个漏斗。先补漏斗，再开渠道。以下按执行顺序。

### 6.1 Windows 0.6.1 装机验证 —— 发布阻塞项
§14 第 5 条：已发布但还没有任何人类装过。只有一次首发流量，不能倒进一个没验证过的安装包。
程序在 `docs/WINDOWS-CHECK.md`。

### 6.2 下载计数快照，**今天**开始
§15.1 明说这是唯一一个"越拖越糟"的项目——GitHub 只报累计总数、不保留历史。宣传前没有基线，
宣传后就无法判断有没有效。同时把口径定死：每次发布 4 个资产，2 个版本名 + 2 个固定名指向
**同一份字节**，全加会双倍计数，只算版本名会漏掉网站按钮的大部分流量。

### 6.3 修首次运行的信任冲突
一个主张"永不发出网络请求"的软件，在第一分钟弹出**键盘监听**权限请求。改的不是架构，是顺序：
零出网这句话必须说在权限弹窗之前，而不是等用户点进设置页才看到。

### 6.4 载入示例项目
§15.3 提到那七张截图来自一个隔离的演示库——**那个库已经存在**。做成"载入示例项目"，让新用户的
第一个动作是在真实项目上按 ⌘⇧P，30 秒内看到 pack 长什么样。这是唯一一个不用积累就能展示积累
的办法，素材已经在硬盘上。

### 6.5 零安装试用
官网直接挂一份真实的 pack `.md`：**"复制这段，粘进你的 AI，看它能不能立刻接住这个项目。"**
pack 就是文本，这是产品形态白送的优势——别人做在线 demo 要写后端，这里只需要挂一个文件。

### 6.6 一个只测不改的项目
Windows 未签名会有一次 SmartScreen 警告。这条 2026-08-15 已决定过，此处**不重提**，
只记成一个待测数字：**Win 与 Mac 的下载比**。数字出来后由 owner 判断。

## 7. 渠道计划

**核心认知转换：现在找到 Spool 的不一定是人，可能是 Agent。**

| 优先级 | 渠道 | 做什么 | 受众 | 成本 |
|---|---|---|---|---|
| 1 | **官方 MCP Registry**（`registry.modelcontextprotocol.io`） | 用 `mcp-publisher` CLI 提交 | 已装 MCP 客户端的人——不需要被说服"上下文丢失"这个问题存在 | 一次提交 |
| 2 | **skills.sh / `npx skills`** | 见下方打法 | 70+ 种 Agent 的用户 | 一个仓库 |
| 3 | **Show HN** | 本地优先 / 零出网 / 确定性，HN 正中靶心 | 英文开发者 | 一次性机会，放在 §6 全部完成之后 |
| 4 | **V2EX 分享创造 → 少数派 → 知乎长文** | 见"最好的素材" | 中文开发者与效率工具人群 | 时间 |
| 5 | **小红书 / 留学申请社群** | 以"申请者本人"的身份写工作流 | 跑多条申请工作流的学生 | 时间 |

### 7.1 MCP Registry
官方注册表主要设计给子注册表程序化消费（Smithery、PulseMCP、Docker Hub、Anthropic、GitHub 等），
提交只需要一个 `mcp-publisher` CLI。**19 个工具 + 7 个 prompt 在整个生态里是少见的完整度，
却不在目录上。**（§14 第 1 条那个"零代码引用的 marketplace 目录"，很可能就是半途放弃的这件事。）

### 7.2 skills.sh 的打法要变
skills 是 Vercel 的开放 agent skills 生态，用 GitHub 当注册表，带目录和排行榜，
CLI 支持 70 多种 Agent；GitHub CLI 2.90 起还有 public preview 的 `gh skill publish`。

**不要发一个"Spool skill"**——没装软件的人拿它没用。
**发那套四带权威格式本身**：任何人装上就能立刻用来组织自己的上下文，而它天然说明
"这个格式 Spool 会自动生成、并且在每条写入路径上强制执行"。

> **送格式，卖生成器。** §16.1 说得很清楚，护城河是**写入路径上的强制执行**，不是那段表头文字；
> 表头本来就印在每一份 pack 上，送出去不亏一分钱。

### 7.3 小红书这条被漏掉了
Owner 就是目标用户本人——一个同时跑多条申请工作流的研究生申请者。这是唯一一个
**受众密度高 + 有第一手可信度 + 现有工具完全不在场**的渠道。"当前版本更适合找工作找学校"
不是短板，是唯一一个能自己站台的市场。

### 7.4 最好的宣传素材不是产品介绍，是测量记录

已经写在 `docs/CASE_STUDY_LEDGER.md` 里、零新增工作量、换个包装就能发的：

- 免费 AI 额度实测比设计假设**少 75 倍**，且随后整个免费层被关掉
- 一个真实项目的 pack 里 **95% 体积来自人粘贴，AI 写入只占 5%**，块大小相差 11 倍
- 外部 AI 第一次通过 MCP 写入，自己造了 **11 个块**、走了一条没人教过的工具链、
  两次出错都自我恢复
- **43 个失败连同修复**；"活着的数据库被清空"那一次
- 新增候选：DeepSeek 压缩成本实测（§5.5）

**人们不会因为你说产品好而下载它。他们会因为读到一篇"我把免费 AI 额度测了一遍，
发现它比所有人以为的少 75 倍"而记住你是谁，然后才顺手点那个下载链接。**
