## 一句话规矩

> **渲染图负责「让人停下来看」，真截图负责「让人相信」。**

海报可以做得好看。**海报后面那一屏必须是真实界面截图**，而且要能被人对着 app 一一核对上。
这不是自我限制 —— 这个产品是靠 `docs/CASE_STUDY_LEDGER.md` 那套测量记录建立信任的，
**被抓到一次图是假的，前面攒的信任全归零。**

| 场合 | 渲染图 |
|---|---|
| 这个目录里的海报 / 视频 / 社媒配图 | ✅ 可以 |
| 紧跟海报之后的「事实依据」那一屏 | ⛔ **必须真截图** |
| 官网功能说明区 / README / 文档 / app 内 | ⛔ 仍然只许真截图 |

## 怎么重新生成

```bash
node docs/promo/build-posters.mjs   # 数据 → HTML
docs/promo/render.sh                # HTML → out/*.png（无头 Chrome，2 倍图）
python3 docs/promo/video/build-video.py   # PNG → mp4
```

除了 Chrome 和 ffmpeg 之外**没有任何依赖**，没有 npm 包要装、要更新、会过期。
改文案只需要改 `build-posters.mjs` 顶部那张表。

## 两段视频

| 文件 | 尺寸 | 时长 | 大小 | 发哪儿 |
|---|---|---|---|---|
| `video/spool-vertical.mp4` | 1080×1440 | 20.5s | 5.3 MB | 小红书 / 抖音 |
| `video/spool-wide.mp4` | 1920×1080 | 20.5s | 5.7 MB | X / Reddit / 官网 |

六个镜头，每个停 4 秒，交叉淡入 0.7 秒，缓慢推拉（一进一出交替）。

**视频是用上面那些海报的 PNG 拼的**，不是另画一套 —— 所以**视频和海报永远不可能对不上数字**，
它们就是同一批像素。无声（社媒默认静音自动播放，配乐还多一份授权要管）。

## 发之前的三条检查

1. ⚠️ **数字必须能被读者自己复算。** `paste` 那两张海报上直接印着 SQL，**别把它裁掉** ——
   这是这套素材和普通广告的唯一区别。
2. ⛔ **不许新造数字。** 账本 §3.13 / §3.14 记着三次「凭空造数字」的事故，
   宣传稿是最容易再犯一次的地方。**没量过就别写。**
3. ⚠️ **素材 #4（外部 AI 首次写入）要发的话必须先脱敏** ——
   账本原文写着 `Publishing requires redaction`，那条记录里的项目名和块内容是真材料。

## 踩过的坑，别再踩

**`zoompan` 的 `d=` 是「每喂进一帧就吐 d 帧」，不是「这个镜头总共 d 帧」。**

第一次编出来的视频是 **7 分钟**，不是 20 秒。原因是输入写成了 `-loop 1 -t 4`，
ffmpeg 按默认 25fps 喂进去 ~100 帧，`zoompan` 对**每一帧**都吐 120 帧 → 12495 帧。

**正确写法是让每个输入只有一帧**：

```
-loop 1 -framerate 1 -t 1 -i poster.png
```

⚠️ **这个错误不会报错**，ffmpeg 退出码 0、文件能播、画面也对 —— **唯一的症状是时长**。
（这个仓库最怕的就是这类沉默失败，见 `CASE_STUDY_LEDGER.md` §3.7。）
改完之后编码还快了 17 倍，因为不再渲染 11775 帧扔掉的画面。
