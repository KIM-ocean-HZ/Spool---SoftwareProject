## 1. 我实际看到的首启(证据)

方法:隔离构建 + `rm -rf ~/Library/Application Support/com.oceanjin.spool.verify` → 启动。
这就是一个陌生人 double-click 之后看到的东西。

### 发现 1:第一眼是**这个产品最空的一屏**

app 开在 **Unsorted** —— 一个**空项目**。两条教程脉络(「Welcome to Spool」、
「Put your AI to work on Spool」)**就躺在左边侧栏里,但没有被打开**。

也就是说:我们辛苦写了 12 块教程内容,而首启把用户放在了旁边那个空房间里。

### 发现 2:最上面一条是权限横幅,内容是「你还得干点活」

> Double-tap ⌥ capture needs the Input Monitoring permission — after granting,
> **fully quit Spool (tray icon → Quit) and reopen**

新装用户 **100% 会看到**(没人预先授权过)。而且它要求的是三步:去系统设置授权 →
**从托盘完全退出**这个刚打开的 app → 再重开。这是用户与产品的第一次对话。

### 发现 3(最要命的一条):屏幕中央那句话,此刻是**半真的**

空状态写着:

> Copy with ⌘C, then double-tap ⌥ to capture your first piece

启动日志实测:

```
[double-tap] Input Monitoring NOT granted — showing system prompt
[double-tap] Input Monitoring request returned granted=false
[double-tap] installed at session/listen-only (no Input Monitoring grant …)
```

`listen-only` 且没有授权,意味着这个 tap **只看得见 Spool 自己的事件**。翻译成人话:

- 在 Spool 窗口里双击 ⌥ —— **有反应**;
- **从 Safari / 邮件 / 任何别的 app 双击 ⌥ —— 什么都不会发生。**

而「从别的 app 里存东西」正是这个产品的**全部意义**。
新用户的必然路径是:看到这句话 → 切到浏览器复制一句 → 双击 ⌥ → **毫无反应** →
得出结论「这软件坏的」→ 删掉。

**他甚至不会知道自己漏了一步**,因为那句话没说「先授权」。

### 发现 4:此刻唯一真的能用的入口,没人指给他

窗口底部那个草稿框(`Write a draft…`)**不需要任何授权**,现在就能存下第一条东西。
它是首启唯一一条「零阻力拿到价值」的路,而空状态一个字都没提它。

### 发现 5:两个系统授权框,在他还不知道这软件有什么用的时候就弹了

代码里 `run_tap()` 一启动就 `CGRequestListenEventAccess()` + 辅助功能提示。
所以时序是:**打开 → 两个吓人的系统弹窗 → 才轮到看产品**。

对一个没听说过的、没有公司背书的软件,这是最坏的顺序:**先要权限,后给价值。**

## 2. 这几条为什么要紧

把上面串起来,一个真实新用户的头 60 秒是这样的:

1. 双击图标 → 弹两个系统授权框(要监听我的键盘?)
2. 关掉弹窗 → 一条横幅说「你还得去授权,然后把我完全退出再打开」
3. 屏幕中央一个空项目,叫他去做一件**此刻做了不会有反应**的事
4. 他照做 → 没反应 → 走了

**我们写好的教程、打包、MCP,他一样都没碰到。** 官网那句「第一个下午就能用上」
在这条路径上是兑现不了的 —— 这也是为什么我把这件事排在推送官网之后的第一位。

## 3. 建议改什么

### 拍板点 1:第一眼开在教程,不要开在空项目(建议:做)

首启(且只有首启)**默认选中「Welcome to Spool」**。理由:
- 那 6 块内容本来就是为这一刻写的,现在被晾着;
- 用户第一眼看到的是**一个装满东西的项目**,顺带就明白了「块、批注、置顶、来源」长什么样;
- 教程第一块就写着捕捉要授权 —— 等于把发现 3 的坑当场填上。

**不改种子内容、不加新 UI**,只改「首启选哪条脉络」。

### 拍板点 2:空状态文案按授权状态分叉(建议:做)

前端已经知道授权状态(横幅就是靠它显示的)。所以:

**没授权时**(现在必然的情况):
> **先在下面写一条试试** —— 打字、按 Enter,它就存下来了,不需要任何权限。
> 想要「在别的 app 里复制就能存」?那一步需要打开输入监听权限。

**已授权时**(保持现在的文案):
> Copy with ⌘C, then double-tap ⌥ to capture your first piece

一句话原则:**永远不要叫用户去做一件此刻会失败的事。**

### 拍板点 3:两个系统授权框推迟到他要用捕捉时再弹(建议:做,但这是唯一要动 Rust 的一笔)

现在:**一启动就弹**。建议:启动只 preflight(不弹),没授权就照常装 listen-only 的 tap
(不影响 Spool 内部的双击),把**主动弹窗**挪到用户点「打开捕捉」那一刻——
横幅上的按钮、或者教程里那一块旁边。

好处是顺序反过来了:**先让他看到东西有用,再要权限。** 要权限的时候他已经知道换来的是什么。

⚠️ 要说清楚的代价:
- 这是行为改动,要改 `src-tauri/src/double_tap.rs` 的 `run_tap()`;
- 「授权后要重启进程才生效」这条**不会消失**(是 macOS 的机制,不是我们的选择),
  所以横幅里那句「完全退出再打开」还得留着,只是挪到他真的授权之后才出现;
- 需要一次隔离构建实机回归(全新 identifier,见 memory `isolated-verify-workflow` §14)。

**如果你觉得这笔太大,可以只批 1、2、4** —— 那三条是纯文案与落地逻辑,
能把发现 3、4 的伤口止住,发现 5 留到以后。

### 拍板点 4:权限横幅改写(建议:做)

现在读起来像「你欠系统一件事」。建议改成「还差一步,以及在此之前你能干什么」:

**EN**
> Capture from other apps needs one permission. Until then, Spool still works —
> write notes below, or copy inside Spool and double-tap ⌥.
> [Turn on capture]

**ZH**
> 想在别的 app 里复制就存,需要开一个权限。在那之前 Spool 照样能用——
> 在下面写笔记,或者在 Spool 里复制后双击 ⌥。
> [打开捕捉]

「完全退出再打开」那句挪到**点了按钮、授权完成之后**再显示(那时它才有意义)。

### 拍板点 5(可选,建议本轮不做):第一条存成之后给个收口

第一次成功捕捉后,在那条块底下出现一句一次性的话:「这就是全部操作了。攒够几条,
按 ⌘⇧P 打包粘给 AI。」—— 会有帮助,但会多一处一次性 UI 状态要维护。**建议以后再说。**

## 5. 验收标准

每一条都必须**在隔离构建上重跑一次全新安装**(删数据目录 → 启动),不许只看代码:

1. 首启落地在「Welcome to Spool」,内容可见 → 截图对照。
2. **未授权状态下,屏幕上没有任何一句话让用户去双击 ⌥ 从别的 app 捕捉** ——
   这是本稿的核心验收,逐字读一遍空状态与横幅。
3. 未授权时按提示在草稿框里写一条 → 存下来了(证明「零权限也能拿到价值」这条路是通的)。
4. 拍板点 3 若批:启动日志里**不再出现** `showing system prompt`;
   点「打开捕捉」后才出现;授权 + 重开后 `installed at HID/active`。
5. 中英各看一遍(硬规则 4),`npx tsc -b` / `npx vitest run` 全绿。

### 7.0 补丁(2026-08-03,Ocean 报的):**教程要从第一块开始展示**

原来打开任何脉络都自动滚到底部(「你上次停在哪」),教程也一样 —— 于是首启落在教程中间,
「Spool 是什么」那一块直接被跳过了。现在的规则:

- **整条脉络还全是种子块**(块的来源都是 `Spool Guide` / `Spool 指南`)→ 打开时停在**最上面**;
- **用户往里捕/写了任何一条自己的东西** → 这条脉络就有「上次停在哪」了,恢复成落到**最新一块**;
- 其他所有脉络行为不变。

判据用来源标签而不是标题,所以改名、切语言都不影响。实机两面都验过。

### 7.1 ⚠️ 顺带测出来的一件事:**注册全局捕捉快捷键会弹「输入监听」框**

第一次验证时我按 memory §15 预置了 `captureShortcut`,结果**首启就弹了输入监听框**——
一度以为拍板点 3 没生效。换全新 identifier、不预置快捷键重测:**一个框都不弹**。
对照结论:那个框来自**注册全局捕捉快捷键**这条路径,不是我们的启动代码。

对真实用户的影响:默认 `captureShortcut` 是 null(2026-07-07 起 ⌘⇧C 退役),
所以**新装用户碰不到**;但**用户一旦在设置里录一个捕捉快捷键,macOS 就会当场要输入监听权限**。
这条没在任何文案里说过,下次动设置页时值得补一句。
