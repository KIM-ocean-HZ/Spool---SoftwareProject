# Static-site QA — 2026-08-13

This is a focused pre-publication check of the repository's five static routes and the changed
Story surface. It is not a production performance report, a cross-browser matrix, or a complete
assistive-technology audit.

## 1. Reproducible visual snapshots

The baseline set covers the **full length** of `/`, `/zh/`, `/story.html`, `/privacy.html`, and
`/zh/privacy.html` at 390, 768, and 1440 CSS pixels. A 1200px viewport is stepped through each
document first so native lazy-loaded assets enter the capture. Captures fix DPR 1, UTC, `en-US`,
sRGB, reduced motion, and settle timing so animation differences do not create false failures.
Chrome DevTools device-metrics override sets the CSS viewport explicitly; this avoids Chrome's
500px minimum headless-window layout silently turning a 390px request into a left-edge crop.

```bash
python3 -m http.server 4173 --directory site
scripts/visual-regression.sh update http://127.0.0.1:4173  # intentional visual change only
scripts/visual-regression.sh check  http://127.0.0.1:4173
```

The 2026-08-13 final check passed all **15 / 15** full-page snapshots with identical dimensions
and zero pixels over the configured delta. The only nonzero sub-threshold variation was a maximum
channel difference of 2 on `/privacy.html` at 768px. The default guard fails if a channel changes
by more than 8 in over 0.1% of pixels, or if any channel differs by more than 32. A successful
check removes current captures and diffs; a failure keeps them for inspection.

Files: `scripts/visual-regression.sh`, `scripts/compare-visual-snapshots.py`, and
`docs/qa/visual-baselines/`. The scripts require Python 3 with Pillow and
`websocket-client`, plus Google Chrome (overridable with `CHROME_BIN`).

## 2. Lighthouse, local mobile defaults

Run with Lighthouse 13.4.1 against the local Python server using its default mobile throttling.
These numbers describe this repeatable local run, **not production performance**.

| Route | Performance | Accessibility | Best practices | SEO | FCP | LCP |
|---|---:|---:|---:|---:|---:|---:|
| `/` | 66 | 100 | 100 | 100 | 5.0s | 5.9s |
| `/zh/` | 65 | 100 | 100 | 100 | 5.0s | 6.2s |
| `/story.html` | 66 | 100 | 100 | 100 | 5.0s | 5.9s |

The audit led to three source fixes: trust-link contrast, semantic heading order on both home
pages, and removal of false headings inside the interactive fake window. Story's architecture
strokes and arrow marker were also darkened to clear the 3:1 non-text contrast requirement.
The real product screenshots remain intentionally legible rather than being over-compressed to
chase a local throttled performance score.

## 3. Focused WCAG 2.1 AA review

- Automated scan: Lighthouse accessibility **100 / 100** on the three changed routes.
- Heading semantics: the problem section uses a real `h2`, its three card titles remain `h3`,
  and fake-window labels are not exposed as document headings.
- Keyboard: a real headless Chrome keyboard run reached the skip link first; activating it moved
  focus to `main#story`. The following 19 focus stops proceeded forward through navigation, all
  eight table-of-contents links, the three screenshot regions, the architecture region, the
  network table, and the first evidence link. Focus rings were visible throughout.
- Scroll regions: each horizontally scrollable Story object is keyboard-focusable and named.
  At the 720 CSS-pixel reflow proxy, the architecture region moved from `scrollLeft 0` to `40`
  using the Right Arrow key while retaining its focus outline and accessible name.
- 200% zoom: actual Chrome page zoom was set to 200% for `127.0.0.1` in an isolated temporary
  profile, then `/`, `/zh/`, and `/story.html` were loaded in a 1440px outer window. Each reported
  `outerWidth = 1440`, `innerWidth = visualViewport.width = 720`, and DPR 2, confirming browser
  zoom rather than a CSS-only proxy. Document and body widths both remained 720px with no
  page-level horizontal overflow; wide evidence stays inside its named local scroll region.
- Images: every Story figure has a caption; all content images have descriptive alt text. The
  three public Story PNGs are generated from the isolated real product scenes, not mockups.
- Responsive matrix: Browser inspection found no page-level horizontal overflow on all five
  routes at 390, 768, and 1440px; Story lazy-loaded images decoded successfully.

Not covered: VoiceOver was **not run**, so this must not be described as a complete formal audit.
Firefox, Safari, production hosting, `/zh/story.html`, physical-device input, and a cross-browser
matrix were deliberately outside this task.
