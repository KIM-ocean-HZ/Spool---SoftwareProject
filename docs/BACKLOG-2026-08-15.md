## 1. Dogfood 发现（2026-08-15，Ocean）

### 1.1 库的提取与迁移

**Ocean 的问题：「现在的发布用户安装新版本之后，数据本身就可以自动迁移吗？」**

**答：同一台机器上原地升级，已经会自动迁移，不需要新功能。** 取证：

- 数据在 `~/Library/Application Support/com.oceanjin.spool/spool.db`，**在 app bundle 之外**。
  装新版 `.dmg` 只替换 `/Applications/Spool.app`，不碰数据目录。
- 启动时 `migrateSchema()`（`src/lib/db/client.ts`）比对 `PRAGMA user_version` 与
  `SCHEMA_VERSION`（当前 **21**），按 `MIGRATIONS` 注册表逐步前进，**每一步单独 checkpoint**，
  中断后下次启动可续。
- 迁移前用 `VACUUM INTO` 自动写一份 `spool.pre-migration-v<旧版本>-<时间戳>.db` 快照。
- 兜底重建分支**拒绝清空非空库**（2026-05-29 事故之后加的防线）。

**所以真正缺的是另一件事：换机器 / 换库时用户可见的入口。** 现在只有终端命令
（`DB_BACKUP_AND_RECOVERY.md` §3），app 内没有「导出库 / 导入库」。

**功能定义**：导出一个自包含的库文件；在新机器导入后照常走 `migrateSchema()` 自动升级到当前
schema。这样「提取出来之后无论 Spool 怎么更新都能迁移过去」这条就由现有迁移链天然保证，
导出格式不需要自己再发明版本兼容。

⚠️ 一条相关事实：**降级会被拒绝启动**（用旧构建打开新库会报错而不是清空）。这是防线不是 bug，
但导入功能的文案要说清楚，否则用户会以为导入失败。

### 1.2 官网 `01 · SAVE` 左图顶部缺失 —— 已定位

**不是 CSS，不是裁图坐标，是源图 `docs/screenshots/S1.png` 的像素里就没有。**

取证：

- S1 第 **0 行**，x = **2895…3544** 已经是浮窗内部的奶油色 `(250, 247, 241)`；
- 浮窗自己的描边色 `(212, 205, 182)` **只在左右两边、从第 2 行才出现**；
- 也就是说**浮窗的上边框和两个圆角根本没被拍进去**。

**产品侧是好的**：`OVERLAY_SCREEN_MARGIN = 20`（`src-tauri/src/capture.rs:642`），
`target_y = m_top + OVERLAY_SCREEN_MARGIN`，浮窗本来离屏幕顶有 20 逻辑像素
（Retina 2x = 40 物理像素）。**不是浮窗贴着屏幕顶。**

**推断**：S1 拍完之后被从顶部裁过（很可能是为了去掉 macOS 菜单栏），这一刀切进了浮窗。

**修法**：重拍，或从没裁过的原图重新导出。
⚠️ **不能用 CSS 补一条边框** —— 那是往截图里画产品本来没有的东西，撞
「不得伪造 / 重绘 / 修改截图里的产品内容」这条硬红线。

**影响面**：左边总览 `capture-page` 和右边细节 #2 `capture-toast` 是**同一批像素**
（`capture-toast` 由 `--cropOffset 0 2880` 从 `capture-page` 裁出），两处一起修。
换掉 S1 之后要重跑 `bash scripts/build-site-shots.sh` → `node scripts/build-site-zh.mjs`，
并更新视觉回归基线。

### 2.1 跟进（Follow Up）换方式 —— 取代 M4 调度器

**Ocean 的判断**：跟进**内容是什么**才是最重要的，不是定时。

目标工作流：

1. 用 MCP 对话后，会留下一些**还没明确的问题**或**还没发生的事情**；
2. 这时希望 **MCP 主动把它们记进跟进内容**；
3. 等捕捉更新了、进入新一轮对话，**MCP 发现这些跟进问题，主动向我汇报，并申请写入 Spool**。

因此 MCP 需要做到两件事：

- **能主动提出**把不确定的信息放进跟进面板；
- **有新的跟进内容时能主动搜索并汇报**；有结论就写入，并**修正或删除**对应的跟进条目。

**手动联网搜索保留，作为用户主动的开关。**

⚠️ 这条**取代**了 `INVESTIGATION_M4_SCHEDULED_FOLLOW_UP_2026-08-13.md` 的调度器方案；
那份报告的 §7 十二个问题**不再需要回答**，它作为「为什么不做定时调度」的论证留档。
新方案的落点是 `DESIGN_FOLLOW_UP.md`，性质从「后台定时任务」变成「MCP 会话内的主动提议 +
待审写入」，**复用现有的待审闸和署名写回机制**，不需要 scheduler、不需要预算/静默条件那一整套。
