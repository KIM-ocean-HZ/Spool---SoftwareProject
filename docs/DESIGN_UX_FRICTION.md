## 2. #5 搁置:自动沉睡(5A,推荐)

**现状问题**:搁置需要用户主动点 pill——但真实行为是"放着不管";且侧栏排序里
parked 与 active 混排(deadline→新近度),搁置的全部效果 ≈ 一枚变灰的 pill。

**5A 设计(全派生,零操作)**:

- 定义:`status != done` 且 `updatedAt` 距今 **> 14 天** → 派生「沉睡」。
- 侧栏:每工作区组内,沉睡项收进组尾一行「沉睡 N 条」(默认折叠,点开展开,
  行 muted);**任何新活动**(捕捉/编辑/AI 写入都会 bump updatedAt)自动浮回。
- 头部:移除 进行中/搁置 pill 对(active 无需自我声明);沉睡脉络的头部显示
  muted「沉睡」字样,有新活动自然消失。done 的 摘要/全记录 切换不动。
- 数据模型**不动**:status='parked' 字段保留(兼容旧数据,旧 parked 线程并入
  沉睡组显示);UI 不再提供手动设 parked 的入口。无 schema 迁移。
- 聚焦区(deadline 火警)优先级高于沉睡:有 deadline 未完成的线程不沉睡。

## 3. #6+#7 侧栏「最近」区(6A,推荐)

**合法性**:VSCode 的文件树之上本来就有 OPEN EDITORS——「最近」区是同一语法;
且侧栏已有先例(聚焦区)。不污染树。

- 位置:侧栏顶部,聚焦区之上;标题「最近」,收 3-5 条最近活动的非 done 脉络
  (updatedAt 降序),**捕捉目标恒置顶**。
- 行设计:标题 + 右侧文字徽标——目标行常驻「捕捉中 ●」(accent 小字);
  非目标行 hover 显示文字按钮「设为捕捉」,点击一键切换目标。点行 = 打开脉络。
  **文字取代 pin 图标**,新用户可读(#7 的侧栏部分就此解决)。
- 树内 ThreadListItem:当前目标行的 pin 图标同步换成「捕捉中」小字;
  其余行 hover 仍是现按钮(title 已有说明)。
- 两区皆空时不占位;沉睡(5A)不进最近区。

## 4. #7 头部捕捉入口(推荐恢复文字钮)

任务三把 设为目标 收进 ⋯ 后新用户无从发现。恢复一个**安静文字钮**在 ⋯ 左侧:

- 非目标:幽灵钮「捕捉到此」(border-line,hover 转 accent);点击即设为目标。
- 是目标:muted 文字「捕捉中 ●」(非按钮,纯状态)。
- ⋯ 菜单里的对应项保留(键盘/习惯路径),两处同源。
