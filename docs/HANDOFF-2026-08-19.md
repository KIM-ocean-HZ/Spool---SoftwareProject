### 1.3 已经查好的技术事实（省得下一窗再量一遍）

- **图在 `src/assets/valentine-background.png`**（1672 × 941，256 色，959 KB），
  已经打进包了，Vite 同源资源，CSP `img-src 'self'` 两个平台都过。
- ⚠️⚠️ **最要紧的一条坑：`background-size: cover` 在小卡片上会取不到花。**
  这张图**花全在四个角，中间大约 x 30%~70% 是近乎纯色的**（`--paper` 就是从那儿取的）。
  一个 340 px 宽的卡片用 `cover` 居中，取到的**正好是中间那块空白**——花一朵都看不见，
  看起来就像「背景图没生效」。
  **解法二选一**（要量，不要猜）：
  - 用 `background-position` 咬住某个角（例如 `bottom right`）＋ `background-size` 放大到卡片的
    好几倍；或者
  - **从原图切一块专用的小图**当第二个资源（角上那朵牡丹 + 几片叶子），弹窗用它，主窗用大图。
    多一个资源，但小卡片的构图能自己控制，我倾向这条。
- **卡片现在的样子**：三类都是 `rounded-lg border border-line-strong bg-paper`。
  `bg-paper` 是**不透明**的，所以想让花透出来，得把它换成半透明或者直接换成背景图＋罩子。
- **浮窗那个窗口本身是透明的**（`src/overlay/style.css` 里 `background: transparent !important`），
  只有卡片可见——所以给浮窗加花是**给卡片加**，不是给窗口加。

### 1.4 ⚠️ 可读性这关照样要过（Ocean:「文字需要看得清」）

弹窗里的字比主界面**更小**（大量 `text-xs` / `text-[11px]` / `text-[12px]`），花又比主界面
**离字更近**，所以**不能照抄主窗那套罩子的数**。

**复用本窗的量法就行**（脚本思路写在 `DESIGN_VALENTINE_EDITION.md §4`）：把候选罩子逐像素
套到图上，算 `--ink` / `--muted` 对每个像素的最坏对比度，再看低于 3 : 1 的面积占比。
主窗那组的结论是 ink 最低 8.96 : 1、muted 低于 3 : 1 的面积 0.8%。**弹窗至少要做到同一档。**

### 1.5 ⚠️ 这件事和 §2 是纠缠的

app 内那 9 个弹窗（②）的**遮罩** `bg-ink/30` 正是 §2 那批死类名之一 ——
**现在它们背后压根没有变暗那一层**。

所以：**如果 Ocean 说的「弹窗」包含 ②，那就要先决定 §2 做不做、什么时候做**，
否则会出现「先按没有遮罩的样子调好了花，§2 一合并遮罩突然出现，全部重调」。
**这两件的顺序要一起问他，别各做各的。**

（③ 休息提醒卡**不受影响**：它的遮罩是写死的 `rgba(58,42,53,.32)` 内联样式，
就是为了绕开这个坑，`BreakReminder.tsx` 里有注释。）

## 2. 【待办 B】119 处死类名 —— 单开分支做，验完没问题再合

### 2.2 病因（已确证，不用再查）

`tailwind.config.js` 里每个颜色都写成 `'var(--paper)'` 这种**完整颜色**的形式。
Tailwind v3 **没法**往一个 CSS 变量里注入 alpha 通道，于是遇到 `bg-ink/30` 这种
**它不报错，直接把整条规则丢掉**。构建全绿、tsc 全绿、测试全绿，什么都不说。

**取证方法（下一窗复核就用这个，别用正则，我第一次就是正则写错差点误判）**：

```bash
npm run build
cd dist/assets
# 字面搜，不是正则
for c in 'bg-ink\/30' 'hover\:bg-paper-2\/60' 'bg-accent\/10'; do
  printf '%-26s hits=%s\n' "$c" "$(grep -F -c "$c" main-*.css)"
done
# 整份 CSS 里带转义斜杠的类，应该只剩布局类
grep -o '[.][^{;, ]*\\/[0-9]*' main-*.css | sort -u
```

本窗结果：六个抽样全 `hits=0`；带转义斜杠的只有 `.left-1\/2` / `.-translate-x-1\/2`（布局类，无关）；
`color-mix` 出现 **0** 次（没有兜底）。

### 2.4 修法

把 token 改成**通道三元组**，config 里用 `<alpha-value>` 占位：

```css
/* tokens.css */
--paper-rgb: 250 247 240;
--paper: rgb(var(--paper-rgb));      /* 直接写 var(--paper) 的地方照旧能用 */
```
```js
// tailwind.config.js
paper: 'rgb(var(--paper-rgb) / <alpha-value>)',
```

⚠️ **两套都要留**：`tokens.css` / `global.css` / `fonts.css` 里有一堆地方是**直接**写
`var(--paper)`、`var(--accent)` 的（不走 Tailwind），把 token 改成纯通道值会**把那些一起弄坏**。
所以是「通道值 + 一个包好的完整颜色」两个 token 并存。

⚠️ **情人节那套 token 也要一起改**，否则修好之后**只有经典版**的透明度生效，情人节版还是死的。

### 2.5 ⚠️⚠️ 爆炸半径 —— 这才是要 Ocean 点头的原因

## 4. 不要重做 / 不要推翻的（本窗已定）

- **经典版 = 发布版本身，不是一个「长得像旧版的主题」。** `tokens.css` 的裸 `:root` 不许动，
  情人节的一切都在 `[data-theme='valentine']` 里，默认 `classic`。
- **`--font-ui` 两个主题都是 Geist**（Ocean:「正常文字不变」）。只有标题字体换。

  爱心用的才是原色。别「修正」回去。
- **搁置/紧急两个状态色故意没改**，它们必须和玫瑰色的 accent 一眼分得开。
